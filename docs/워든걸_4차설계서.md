# 워든걸 (WardenGirl) — 4차 설계서

**환경:** Minecraft 1.20.1 / Forge 47.4.10 / Java 17 / official mappings / GeckoLib 4.8.4  
**기준 구현:** 3차 완료 기준 `527857c`  
**태스크 연속성:** 3차의 `T23`은 **완료 및 승인** 상태다. `T24`·`T25`·`T26`은 **의도적으로 스킵**했으며 미완료 대기 태스크가 아니다 — 4차 구현 중 다시 구현하거나 선행 조건으로 요구하지 않는다. 4차는 `T27`부터 시작한다.  
**4차 범위:** 플레이어 수준 이상의 지형 이동, 안전 하강, 투사체 회피, 근접 회피·반격, 플레이어 조준선 회피  
**문서 성격:** 구현 지시서. 이 문서에 없는 이동·전투 기능은 만들지 않는다.

---

## Part 0. 구현자 준수사항

이 문서를 읽는 구현자(Claude Code)는 다음을 반드시 지킨다.

1. **한 태스크가 끝나면 반드시 멈춘다.** 다음 태스크로 자동 진행하지 않는다.
2. **현재 코드와 Minecraft 1.20.1 공식 매핑을 먼저 확인한다.** API 이름, 물리 상수, `DamageSource`, `PathNavigation`, `Projectile`, `LivingEntity` 동작을 기억으로 추정하지 않는다.
3. **바닐라 이동을 항상 우선한다.** 정상적인 바닐라 경로로 해결되는 상황에 특수 이동을 억지로 사용하지 않는다.
4. **특수 이동은 실제 서버 물리로 수행한다.** 순간이동, noclip, 블록 관통, 착지점 강제 스냅, 실패 롤백으로 성공을 꾸미지 않는다.
5. **서버가 판정한다.** 이동 선택, 안전 검사, 투사체 충돌 예측, 회피 확률, 피해 취소, 카운터 피해는 서버 권위다.
6. **클라이언트는 표현만 담당한다.** 서버가 확정하지 않은 회피·공격·착지 결과를 클라이언트가 만들지 않는다.
7. **멀티플레이 전용 분기를 만들지 않는다.** 싱글플레이도 동일한 서버 로직을 사용한다.
8. **기존 소유자·아군 필터를 유지한다.** 소유자와 같은 소유자의 워든걸을 공격·카운터하거나, 그 관계의 투사체를 적대 투사체로 오인하지 않는다.
9. **기존 중립 전투·후퇴·소닉·추종·문 구조를 유지한다.** 4차 기능이 T14~T23의 우선순위를 무시하지 않는다.
10. **특수 이동 중 다른 특수 이동을 겹치지 않는다.** 한 개체에 실행 중인 특수 이동 계획은 최대 하나다.
11. **회피는 무적 상태가 아니다.** 성공한 특정 근접 공격 한 건만 취소한다. 회피 중 다른 공격은 정상적으로 맞을 수 있다.
12. **확정된 범위를 임의 확장하지 않는다.** 자유 등반, 공중제비, 벽차기 연속 콤보, 물 낙하, 포션 회피 등을 추가하지 않는다.
13. **검증 명령에 핵심 기능을 구현하지 않는다.** 명령은 개체 API와 실제 판정 경로를 호출하는 테스트 진입점이다.
14. **검증 명령의 runtime override는 NBT에 저장하지 않는다.** 재접속·청크 재로드 후 자동 해제돼야 한다.
15. **애니메이션 수치는 첫 시안을 보고한다.** 사람 확인 전에 “자연스럽다”고 자체 확정하지 않는다.
16. **[사람 확인]은 구현자가 통과 판정하지 않는다.** 실제 화면 판단은 사람이 한다.
17. **완료 보고는 구체적으로 한다.** 실행 명령, 측정 좌표, 틱, 속도, 피해 전후 체력, 실패 사례를 함께 보고한다.

## Part 1. 프로젝트 목표와 범위

### 1.1 4차에서 무엇을 만드는가

4차의 목적은 워든걸이 일반 몹처럼 작은 지형 단절 앞에서 멈추지 않고, 사람형 전투 동료답게 짧은 장애물을 실제 움직임으로 극복하며 공격을 회피하게 하는 것이다.

| 축 | 기능 |
|---|---|
| **기본 지형 이동** | 유격 1~3블록을 플레이어처럼 일반 점프로 통과 |
| **장거리 지형 이동** | 유격 4~5블록을 준비 후 다이브 점프로 통과 |
| **수직 장애물** | 정확히 2블록 벽을 도움닫기·팔·발 반동으로 넘어감 |
| **하강** | 피해 없는 짧은 낙하, 절벽 정지, 벽 매달림 하강 |
| **투사체 회피** | 자신에게 충돌할 단일 투사체를 좌우 사이드홉으로 회피 |
| **소형 근접 회피** | 확률적으로 뒤로 튀어 피해를 취소하는 백 회피 |
| **대형 근접 회피** | 확률적으로 대각선으로 튀며 공격을 취소하고 카운터 |
| **플레이어 전투** | 현재 전투 대상 플레이어의 조준선을 피하고, 근접 피격 시 대각선 패링·카운터 |
| **검증 기반** | 이동·전투 상태를 독립 검증하는 운영자 명령 |

### 1.2 핵심 컨셉

> **“바닐라 길찾기를 버린 파쿠르 몹이 아니라, 바닐라 길찾기가 해결하지 못한 가까운 단절만 실제 몸으로 넘고, 전투에서는 짧고 명확한 회피를 사용하는 사람형 동료.”**

### 1.3 바닐라 우선 원칙

판정 순서는 다음과 같다.

```text
현재 목적지 존재
→ 정상 바닐라 path 생성 시도
→ 정상 path가 유효하면 바닐라 이동
→ path가 국소 장애물 앞에서 끝나거나 명백히 실패
→ 장애물 형태를 분류
→ 허용된 특수 이동 하나를 검사
→ 안전하면 실행
→ 종료 후 원래 목적지로 새 바닐라 path 계산
```

특수 이동은 월드 전체를 다시 길찾는 시스템이 아니다. 출발점과 가까운 장애물 한 개를 넘는 일회성 연결이다.

### 1.4 이번 4차에서 명시적으로 제외하는 것

다음 기능은 구현하지 않는다.

- 물을 향해 뛰어내리는 `water_dive`
- 투척 포션·잔류 포션·`AreaEffectCloud` 회피
- 모서리를 붙잡고 기어오르는 `ledge_recovery`
- 자유 등반
- 3블록 이상 벽 오르기
- 유격 6블록 이상 도약
- 사다리 없는 벽 연속 등반
- 벽 사이 연속 반동
- 공중제비
- 적의 머리 위로 뛰어넘기
- 장거리 슬라이딩
- 공중 방향 자유 변경
- 실패한 이동의 원위치 롤백
- 모든 낙하 피해 면역
- 회피 중 전체 피해 면역
- 즉발 광선·불투명한 모드 공격 완전 예측
- 주변 모든 플레이어의 조준선을 동시에 피하는 계산
- 전투 원형 돌기, 별도 전투 돌진, 포션 대응 등 이 문서에 없는 전투 기동

## Part 2. 공통 기술 구조

### 2.1 기존 이동 목적을 재사용한다

특수 이동은 목적지를 새로 만들지 않는다. 다음 기존 목적 중 하나를 이어받는다.

- 소유자 추종
- 유효한 전투 대상 추격
- 저체력 FLEE 안전 지점 이동
- 검증 명령의 고정 시험 목적지

무작위 배회에는 4~5블록 다이브, 2블록 벽 박차기, 벽 매달림 하강을 사용하지 않는다.

유격 1~3블록 일반 점프와 피해 없는 짧은 낙하는 일반 이동 흐름에서 허용할 수 있으나, 무의미한 왕복이나 지름길 반복이 생기지 않아야 한다.

### 2.2 특수 이동 상태

런타임 상태는 최소한 다음 종류를 구분한다.

```text
NONE
SPRINT_GAP_JUMP
GAP_DIVE_PREPARE
GAP_DIVE_AIR
WALL_REBOUND_RUNUP
WALL_REBOUND_AIR
SHORT_DROP
WALL_DESCENT_GRIP
WALL_DESCENT_RELEASE
SIDE_HOP
BACK_DODGE
DIAGONAL_COUNTER
PLAYER_AIM_EVADE
```

`PLAYER_AIM_EVADE`는 공중 특수 이동이라기보다 현재 전투 이동 방향을 일정 시간 유지하는 상태다. 다른 공중 이동 상태와 동시에 새로 시작하지 않는다.

### 2.3 일회성 이동 계획

특수 이동 계획은 런타임에만 둔다.

필수 정보:

```text
이동 종류
출발 위치
고정 착지 또는 종료 위치
출발 방향
원래 이동 목적 종류
원래 목적지 또는 대상 UUID
시작 서버 tick
현재 단계
예상 종료 tick
사용한 벽 면 또는 투사체 UUID
```

저장하지 않는다. 청크 언로드·재접속 후에는 `NONE`에서 정상 AI를 다시 계산한다.

### 2.4 MOVE 제어권

실행 중인 특수 이동 하나가 MOVE 제어권을 가진다.

- 공중 특수 이동 중 navigation이 속도를 덮어쓰지 않는다.
- 특수 이동이 끝나면 navigation 제어권을 반환한다.
- 소닉은 기존 T21 구조처럼 상체 행동과 하체 이동을 분리할 수 있다.
- 새 Goal 숫자는 현재 selector를 확인해 정하되 의미상 우선순위를 지킨다.

### 2.5 공통 안전 판정

모든 이동 후보는 서버에서 다음을 검사한다.

1. 필요한 청크가 이미 로드돼 있음
2. 출발점이 안정된 지면이며 즉시 도약 가능한 상태
3. 도착 AABB가 블록과 충돌하지 않음
4. 머리와 몸 공간이 충분함
5. 도착점 아래에 허용된 바닥이 있음
6. 착지점에 다른 `LivingEntity` AABB가 겹치지 않음
7. 이동 궤적 또는 sweep AABB가 블록과 충돌하지 않음
8. 용암, 불, 선인장, 피해 블록을 밟지 않음
9. 허용되지 않은 추가 낙차가 없음
10. 소유자 leash와 기존 T14 장거리 규칙을 위반하지 않음
11. 원래 목적지에 실제로 가까워지거나 현재 위험에서 벗어남
12. 최근 동일 연결 실패 기억에 걸리지 않음

### 2.6 국소 장애물 분류

정상 path가 끝난 지점에서 가까운 전방만 검사한다.

```text
같은 높이 수평 유격 1~3 → SPRINT_GAP_JUMP
같은 높이 수평 유격 4~5 → GAP_DIVE
정확히 2블록 높이 벽 → WALL_REBOUND
아래 낙차가 바닐라 피해 0 → SHORT_DROP
피해가 발생하는 낙차 + 연속 벽 → WALL_DESCENT
그 외 → 특수 이동 없음
```

문은 기존 T23이 담당한다. 4차 장애물 분류기가 문을 벽 박차기 대상으로 처리하지 않는다.

### 2.7 시작 전 재검사와 목표 고정

후보를 고른 뒤 실제 시작 직전에 다음을 다시 확인한다.

- 원래 목적이 아직 유효한가
- 착지점이 비어 있는가
- 출발점·벽·궤적이 바뀌지 않았는가
- 개체가 지상에 있는가
- 다른 특수 이동이 시작되지 않았는가

도약이 시작된 뒤 착지점을 바꾸지 않는다.

### 2.8 실패 처리

- 순간이동으로 성공시키지 않음
- 출발점으로 되돌리지 않음
- noclip 사용 안 함
- 낙하 피해를 임의 취소하지 않음
- 실제 벽·지면 충돌과 중력 결과를 받아들임
- 같은 출발 블록·목표 블록·이동 종류 조합을 짧게 기억해 즉시 재시도하지 않음

초기 실패 기억 시간은 **40틱**으로 한다. 수치가 부적절하면 측정값과 함께 보고하고 임의 변경하지 않는다.

### 2.9 이동 종료 후 경로 복귀

모든 지형 특수 이동 종료 시:

```text
원래 목적 유효성 재검사
→ 현재 위치에서 새 바닐라 path 생성
→ 기존 추종·추격·FLEE 동작 재개
```

특수 이동 착지 후 멈춰 서는 상태가 남지 않아야 한다.

### 2.10 공중 상태 공통 규칙

다음 중 하나면 새 사이드홉·백 회피·대각선 회피를 시작하지 않는다.

- `onGround == false`
- 이미 점프 또는 특수 이동 공중 단계
- 4~5블록 다이브 준비 중
- 2블록 벽 박차기 도움닫기·도약 중
- 벽 매달림 하강 중
- 다른 회피 동작 중

별도 시간 쿨다운은 두지 않는다. 착지해 정상 지상 상태가 되면 다음 공격부터 다시 판정할 수 있다.

## Part 3. 개발·검증용 명령 체계

### 3.1 목적

4차는 자연 발생 조건을 만들기 어려운 이동과 확률 회피가 많다. 따라서 각 태스크를 독립적으로 검증할 운영자 명령을 먼저 만든다.

명령은 실제 개체 API를 호출하며, 명령 내부에서 이동·피해·회피 로직을 따로 복제하지 않는다.

모든 명령은 기존 `/wardengirl` 루트 아래에 두고 **permission level 2**를 요구한다.

### 3.2 명령 목록

```text
/wardengirl test teleport <wardenGirl> <player>
/wardengirl test move to_player <wardenGirl> <player>
/wardengirl test target set <wardenGirl> <livingEntity>
/wardengirl test target clear <wardenGirl>
/wardengirl test attack_damage set <wardenGirl> <value>
/wardengirl test attack_damage clear <wardenGirl>
/wardengirl test dodge_chance set <wardenGirl> <back|diagonal|player> <percent>
/wardengirl test dodge_chance clear <wardenGirl> <back|diagonal|player|all>
/wardengirl test projectile fire <wardenGirl> <player>
/wardengirl test melee_hit <wardenGirl> <attacker>
/wardengirl test movement cancel <wardenGirl>
/wardengirl test state get <wardenGirl>
```

### 3.3 `test teleport`

워든걸을 지정 플레이어의 현재 서버 위치로 이동한다.

- 같은 차원이 아니어도 서버가 허용하는 실제 차원 이동 API를 사용한다.
- 탑승 중이면 안전하게 하차시킨다.
- navigation과 현재 특수 이동을 중단한다.
- `fallDistance`를 0으로 초기화한다.
- 소유권과 target은 변경하지 않는다.
- 플레이어와 겹친 뒤 바닐라 밀치기가 발생할 수 있으며 이를 숨기지 않는다.

대표 명령:

```mcfunction
/wardengirl test teleport @e[type=wardengirl:warden_girl,sort=nearest,limit=1,distance=..32] @s
```

### 3.4 `test move to_player`

명령 실행 순간의 플레이어 발 위치를 **고정 시험 목적지**로 저장한다.

- 이후 플레이어가 움직여도 시험 목적지는 움직이지 않는다.
- 실제 바닐라 path와 4차 장애물 분류를 사용한다.
- 특정 이동을 강제로 성공시키지 않는다.
- 다른 실제 전투·후퇴가 시작되면 시험 목적지를 취소한다.
- NBT에 저장하지 않는다.

대표 명령:

```mcfunction
/wardengirl test move to_player @e[type=wardengirl:warden_girl,sort=nearest,limit=1,distance=..64] @s
```

### 3.5 `test target`

플레이어 전투와 추격을 검증하기 위한 runtime target 명령이다.

- `set`은 기존 공통 `canAttack`과 소유 관계 필터를 통과해야 한다.
- 소유자·같은 소유자의 워든걸·창조 모드·관전자 등 기존 제외 대상을 강제로 우회하지 않는다.
- `clear`는 test target만 지우고 다른 영구 데이터를 바꾸지 않는다.

### 3.6 `test attack_damage`

플레이어 전투를 관찰할 때 워든걸의 직접 근접 피해를 0으로 만들기 위한 runtime override다.

```mcfunction
/wardengirl test attack_damage set @e[type=wardengirl:warden_girl,sort=nearest,limit=1,distance=..32] 0
```

규칙:

- 값은 0 이상 유한 `double`
- 일반 근접 공격과 대각선 카운터가 같은 유효 공격력 getter를 사용
- 소닉 피해는 변경하지 않음
- PowerStacks, Attribute base value, 저장된 성장값을 손상시키지 않음
- NBT 저장 안 함
- `clear` 시 현재 성장 스탯의 정상 근접 공격력으로 즉시 복귀

### 3.7 `test dodge_chance`

확률 회피를 결정적으로 검증하기 위한 runtime override다.

예:

```mcfunction
/wardengirl test dodge_chance set <wardenGirl> back 100
/wardengirl test dodge_chance set <wardenGirl> diagonal 100
/wardengirl test dodge_chance set <wardenGirl> player 100
```

- 실제 기본 확률을 변경하지 않는다.
- 0~100 범위 정수 또는 실수 퍼센트
- NBT 저장 안 함
- `clear all`로 모든 override 해제
- 안전한 착지점이 없으면 100%라도 회피하지 않는다.

### 3.8 `test projectile fire`

지정 플레이어 눈 위치 부근에서 워든걸 중심을 향해 **소유자 없는 바닐라 화살 1발**을 발사한다.

- 실제 `Arrow` 엔티티와 실제 속도·중력·충돌을 사용
- 워든걸이 현재 위치에서 맞을 수 있도록 서버에서 방향 계산
- 사이드홉 로직을 직접 호출하지 않음
- 다중 투사체를 한 명령으로 만들지 않음

### 3.9 `test melee_hit`

지정 공격자를 출처로 하는 실제 근접형 `DamageSource` 한 건을 워든걸에 적용한다.

- 회피 판정이 `hurt` 진입 경로에서 실제로 피해를 취소하는지 검증
- 공격자 AABB 크기와 Player 여부를 실제로 분류
- 투사체·마법·폭발 피해로 위장하지 않음
- 피해량은 검증 가능한 고정 소량으로 하되, 현재 코드에 이미 공용 테스트 피해 API가 있으면 재사용

### 3.10 `test state get`

최소 출력 항목:

```text
entity id / UUID
owner UUID 유무
현재 target
현재 test destination
현재 special movement state와 phase
start / landing / wall block
onGround / horizontalCollision / fallDistance
현재 deltaMovement
navigation isDone
최근 실패 연결과 남은 실패 기억 tick
attack damage test override
back / diagonal / player dodge chance override
현재 player aim evade 방향과 남은 유지 tick
현재 감지한 projectile UUID와 예상 충돌 tick
```

### 3.11 명령의 저장·배포 원칙

- 모든 `test` 상태는 runtime only
- 저장·로드 후 자동 해제
- 명령 제거 여부는 4차 완료 후 사람이 결정
- permission 2 아래에 있으므로 일반 생존 플레이어는 사용할 수 없음
- 명령 실패 시 원인을 명확히 출력: 잘못된 대상, 안전 후보 없음, 다른 차원, 관계 필터, 공중 상태 등

## Part 4. 지형 이동 상세 규격

### 4.1 유격 정의

이 문서의 “유격 N블록”은 출발 블록과 착지 블록 사이의 **빈 블록 수**다.

```text
유격 3블록
출발 | 공기 | 공기 | 공기 | 착지
중심 간 수평 차이 4블록
```

### 4.2 유격 1~3블록 일반 점프

#### 4.2.1 목적

일반 몹 AI가 처리하지 못하는 짧은 수평 단절을 플레이어의 달리기 점프처럼 넘는다.

#### 4.2.2 애니메이션

새 전용 애니메이션을 만들지 않는다.

- 기존 걷기·달리기 표현
- 바닐라 실제 점프와 공중 자세
- 기존 착지 전환

웅크리기, 다이브, 손 착지, 슬라이딩을 추가하지 않는다.

#### 4.2.3 조건

- 유격 1~3블록
- 출발과 착지 바닥 높이가 같음
- 착지 블록이 완전한 안전 지면
- 착지 후 진행 방향으로 최소 1블록 이상 계속 설 수 있음
- 궤적의 몸·머리 공간이 비어 있음
- 현재 목적지가 틈 반대편
- 지상 상태

#### 4.2.4 실행

가장자리까지 달리기 흐름을 유지하고 실제 점프 속도를 부여한다.

- 도약 전 강제 정지 없음
- 수평 관성 유지
- 공중 조향으로 착지점을 수정하지 않음
- 착지 후 원래 목적지 path 재계산

### 4.3 유격 4~5블록 다이브 점프

#### 4.3.1 목적

일반 점프 범위를 넘는 유격을 워든걸 전용 다이브 점프로 넘는다.

#### 4.3.2 시작 조건

- 유격 정확히 4 또는 5블록
- 출발과 착지 바닥 높이가 같음
- 안전하고 충분한 착지 폭
- 전체 비행 sweep가 비어 있음
- 유효한 목적지가 반대편
- 정상 우회 path가 적절히 존재하지 않음
- 지상이며 다른 특수 이동 없음

6블록 이상은 시도하지 않는다.

#### 4.3.3 동작

```text
가장자리 접근
→ 완전 정지
→ 제자리에서 자세 준비
→ 착지점을 향해 강한 전방·상방 도약
→ 몸을 앞으로 뻗는 다이브
→ 발과 손을 이용한 낮은 착지
→ 짧은 중심 회복
→ 원래 이동 재개
```

도움닫기 장거리 점프가 아니라 **가장자리에서 멈추고 준비한 뒤 발사되는 다이브**다.

초기 애니메이션 목표:

```text
준비 4~6틱
공중 8~12틱
착지·회복 3~4틱
```

실제 거리에 따라 공중 시간은 물리 결과를 따르며 애니메이션이 위치를 끌고 가지 않는다.

#### 4.3.4 넉백

- 넉백 저항 100%이면 피해를 받아도 다이브를 계속한다.
- 100% 미만이며 실제 넉백이 속도·궤적을 흐트러뜨리면 다이브 계획을 실패 처리한다.
- 실패 후 강제 착지·복귀 없음
- 이후 실제 물리대로 낙하

### 4.4 2블록 벽 박차고 오르기

#### 4.4.1 의미

정확히 2블록 높이의 벽을 **기어오르지 않고**, 멀리서 팔을 들고 달려와 손과 발로 짧게 박차며 한 번에 넘어간다.

#### 4.4.2 지형 조건

- 진행 방향 전방에 정확히 2블록 높이의 연속 충돌면
- 3번째 블록 높이는 비어 있음
- 벽 위 또는 벽 뒤에 안전한 착지 지면
- 도움닫기 공간 최소 3블록
- 벽 뒤에도 계속 이동 가능한 지면
- 머리·몸 궤적이 비어 있음

제외:

- 울타리, 철창, 문, 다락문, 울타리문
- 선인장, 불, 용암
- 움직이는 피스톤
- 불규칙하거나 얇은 충돌면
- 낮은 천장
- 3블록 이상 벽

#### 4.4.3 동작

```text
벽에서 3블록 전후 위치로 이동
→ 벽을 보며 달리기 시작
→ 달려오면서 양팔을 앞·위로 듦
→ 점프
→ 손으로 벽 상단을 누르고 발로 벽을 짧게 박참
→ 전방·상방 반동으로 몸을 빠르게 넘김
→ 벽 위 또는 뒤에 발부터 착지
```

벽 접촉 강조는 **1~2틱** 정도로 짧게 한다.

팔꿈치·무릎을 세밀하게 번갈아 움직이는 등반 표현을 만들지 않는다. 마인크래프트 관절에서 “매달려 기어오름”이 아니라 “빠른 반동으로 박차고 올라감”으로 보여야 한다.

#### 4.4.4 실제 물리

- 실제 충돌 후 반사 벡터에 의존하지 않음
- 시작 전 계산한 안전 궤적에 맞춰 점프와 짧은 추가 전방·상방 속도를 부여
- AABB가 벽을 관통하지 않음
- 벽 위로 위치를 직접 이동시키지 않음

### 4.5 피해 없는 짧은 낙하

#### 4.5.1 조건

현재 위치에서 착지점까지 실제 바닐라 낙하 피해 계산 결과가 **0**일 때만 허용한다.

고정 높이 상수를 별도로 만들기보다 현재 효과·상태를 포함한 실제 1.20.1 낙하 계산을 확인한다.

#### 4.5.2 동작

- 정상 걸음 또는 점프에서 가장자리를 벗어남
- 별도 특수 애니메이션 없음
- 낙하 피해 면역 없음
- 착지 후 원래 path 재개

### 4.6 절벽 정지 `edge_brake`

허용된 하강 계획이 없는데 앞쪽에 낙하 피해가 발생하는 절벽이 있으면 가장자리 전에 감속·정지한다.

적용 대상:

- 일반 추종·추격
- 플레이어 조준 회피
- 사이드홉 후보
- 백·대각선 회피 후보

`edge_brake`는 독립 Goal이나 긴 애니메이션이 아니라 안전 규칙이다.

### 4.7 벽 매달림 하강

#### 4.7.1 목적

그대로 떨어지면 낙하 피해를 입는 높이에서 벽을 팔다리로 붙잡고 마찰시키며 내려와, 안전한 높이에서 손을 놓고 정상 착지한다.

#### 4.7.2 시작 조건

- 아래 목적지로 정상 path 없음
- 현재 낙차는 바닐라 피해가 발생함
- 몸 옆 또는 전방에 하강 구간 전체를 지지할 연속 충돌 벽 존재
- 몸이 내려갈 세로 공간이 비어 있음
- 아래에 안전한 지면 존재
- 벽이 중간에 끊기지 않음
- 벽 재질이 허용됨

제외 블록은 2블록 벽 규칙과 동일하며 얇고 불연속적인 충돌면은 사용하지 않는다.

#### 4.7.3 자세

```text
몸은 벽 방향
양팔은 위로 들어 벽을 붙잡음
다리는 아래 지면 방향
손과 발을 벽에 마찰시키며 하강
```

기어 내려오는 동작이 아니다.

- 팔다리를 번갈아 큰 폭으로 옮기지 않음
- 팔·손목·다리·몸통에 미세한 비대칭 떨림과 작은 움직임
- 완전히 고정된 마네킹 자세 금지
- 다리는 착지에 자연스럽게 이어지도록 계속 아래를 향함

#### 4.7.4 시선

몸 방향은 벽을 유지하지만 머리는 허용 범위 안에서 움직일 수 있다.

- 현재 target 또는 소유자를 제한적으로 바라볼 수 있음
- 몸을 벽에서 떼는 과도한 회전 금지
- 머리를 벽에 고정하지 않음
- 위·아래 시선도 자연스러운 범위 허용

#### 4.7.5 하강 물리

벽 접촉 중 하강 속도의 절대값을 제한한다. 초기 목표 최대 하강 속도는 **0.20 block/tick**이다.

- 벽 접촉 중 `fallDistance`를 누적하지 않음
- 벽에서 멀어지는 수평 속도를 제한
- 실제 벽 접촉이 없으면 감속하지 않음
- 일반적인 낙하 전체를 면역 처리하지 않음

#### 4.7.6 가루 파티클

손과 발 접촉점에서 실제 벽 `BlockState`의 파괴 입자를 발생시킨다.

- 서버가 실제 벽 블록을 결정
- 클라이언트에 정상 입자 전송
- 블록 파괴·상태 변경 없음
- 초기 간격 평균 3틱
- 매번 네 지점 모두가 아니라 손·발 중 일부를 비대칭적으로 선택
- 입자는 소량으로 유지

#### 4.7.7 안전 높이에서 자발적 해제

지면에 발이 닿을 때까지 매달리지 않는다.

```text
현재 위치에서 손을 놓음
→ 아래 지면까지 자유 낙하했을 때 바닐라 피해 0
→ 벽 매달림 종료
→ 짧은 정상 낙하
→ 발부터 착지
```

#### 4.7.8 넉백과 낙하 거리

넉백 저항 100%:

```text
벽 접촉 유지
→ 그대로 계속 하강
```

넉백을 받았지만 벽과 실제 유격이 생기지 않음:

```text
같은 tick 또는 다음 판정에서 벽 접촉 유효
→ 자세가 잠깐 흐트러짐
→ 다시 붙잡은 상태로 계속 하강
```

넉백으로 벽을 짚을 수 없는 실제 간격이 생김:

```text
벽 접촉 상실
→ 즉시 자유 낙하
→ 접촉을 잃은 현재 높이부터 fallDistance 새로 누적
```

예:

```text
지면 위 50블록에서 벽 하강 시작
→ 벽을 잡고 40블록 하강
→ 지면까지 10블록 남은 위치에서 넉백으로 벽과 분리
→ 10블록 낙하로 판정
```

이미 벽을 잡고 내려온 40블록을 낙하 피해에 다시 더하지 않는다. 반대로 떨어진 뒤 공중에서 벽과 가까워졌다는 이유로 자동 재부착하지 않는다.

## Part 5. 전투 회피 상세 규격

### 5.1 공통 피해 회피 원칙

백 회피·대각선 회피·플레이어 대각선 패링은 실제 근접 피해가 적용되려는 순간에 확률을 판정한다.

```text
근접 DamageSource 진입
→ 공격자 식별
→ 공중·다른 회피 상태 검사
→ 회피 종류 분류
→ 고정 확률 판정
→ 안전한 목적지 검사
→ 성공하면 super.hurt 이전에 해당 피해 한 건 취소
→ 회피 동작 시작
```

성공 시 다음 피격 표현이 발생하지 않아야 한다.

- 체력 감소
- 붉은 피격 점멸
- hurt 애니메이션
- 피해자 피격음
- 일반 피격 넉백
- 해당 공격으로 인한 `hurtTime` 시작

다만 공격 시도 자체는 적대 사건이므로, 기존 관계상 유효한 공격자라면 전투 대상으로 인식할 수 있어야 한다.

### 5.2 회피 확률

거리 보정 없이 고정값을 사용한다.

초기 확정값:

```text
백 회피             : 25%
대형 몹 대각선 회피 : 20%
플레이어 대각선 패링: 20%
```

- 매 실제 근접 공격 시도마다 독립 판정
- 시간 쿨다운 없음
- 회피 동작 또는 공중 체류 중에는 새 회피 발동 없음
- 착지하면 즉시 다음 공격부터 다시 판정
- 안전 후보가 없으면 확률에 성공해도 정상 피격

### 5.3 투사체 사이드홉

#### 5.3.1 대상

자신에게 실제로 충돌할 것으로 예상되는 단일 비행 투사체 한 발을 처리한다.

포함 예:

- 화살
- 스펙트럴 화살
- 삼지창
- 위치·속도·충돌이 정상 노출되는 유사 단일 Projectile

제외:

- 투척·잔류 포션
- 효과 구름
- 즉발 광선
- 소닉붐
- 이미 박힌 투사체
- 워든걸에서 멀어지는 투사체
- 현재 궤적으로 충돌하지 않는 투사체
- 소유자·같은 소유자 관계로 피해가 무효인 투사체

#### 5.3.2 충돌 예측

초기 검사 범위와 시간:

```text
수평 탐지 반경 : 12블록
최대 예상 시간 : 12틱
```

서버에서 투사체와 워든걸의 현재 위치·속도를 사용해 상대 운동을 예측하고, 예상 sweep가 워든걸 AABB와 교차하는지 검사한다.

여러 발이 있더라도 완전한 탄막 회피를 계산하지 않는다. 가장 먼저 충돌할 한 발만 후보로 삼으며, 좌우 어느 쪽도 안전하지 않으면 피하지 않는다.

#### 5.3.3 발동 가능 상태

가능:

- 가만히 서 있음
- 걷는 중
- 달리는 중
- 지상 추격·추종 중

불가:

- 공중 체류 중
- 유격 점프 중
- 4~5블록 다이브 준비·실행 중
- 2블록 벽 박차기 중
- 벽 하강 중
- 다른 회피 중

#### 5.3.4 이동 방향

좌우는 워든걸의 시선이 아니라 투사체 수평 진행 방향의 수직 방향으로 만든다.

- 왼쪽 후보
- 오른쪽 후보

현재 이동 성분을 유지한다.

```text
정지 중 → 순수 측면 홉
걷는 중 → 전진 + 측면 홉
달리는 중 → 달리기 관성 + 대각선 측면 홉
```

초기 측면 목표 거리는 **2.5블록 전후**다. 실제 안전 후보와 충돌 검사로 조정하되 임의로 범위를 넓히지 않는다.

#### 5.3.5 애니메이션

하나의 짧은 사이드홉 클립을 좌우 반전해 사용한다.

- 한쪽 발로 지면을 밀어냄
- 몸을 낮고 짧게 띄움
- 반대쪽 발부터 착지
- 팔은 균형을 잡되 과도하게 벌리지 않음
- 현재 걷기·달리기 속도와 자연스럽게 합성
- 긴 착지 경직 없음

### 5.4 백 회피

#### 5.4.1 대상 분류

공격자의 수평 AABB 폭이 비교적 작은 근접 공격을 대상으로 한다.

예:

- 좀비
- 우민
- 엔더맨
- 피글린
- 일반적인 사람형 소형 폭 Mob

종류 목록만으로 하드코딩하지 않는다. 기본 분류는 실제 수평 AABB 폭이다.

초기 기준:

```text
attacker horizontal width < 0.90블록
→ 백 회피 후보
```

플레이어는 폭이 작아도 별도 규칙으로 대각선 패링 후보다.

#### 5.4.2 동작

피격 순간 별도 준비 딜레이 없이 공격자 반대 방향으로 즉시 튀어 오른다.

```text
피해 취소
→ 몸이 뒤로 들림
→ 짧고 낮게 후방 도약
→ 발부터 착지
```

단순한 지상 미끄러짐이 아니라 두 발이 지면에서 떨어지는 즉각적인 도약이다.

초기 후방 목표 거리는 **2.0블록 전후**다.

#### 5.4.3 안전 실패

뒤쪽에 다음이 있으면 회피하지 않고 정상 피해를 받는다.

- 벽
- 머리 공간 부족
- 낭떠러지
- 용암·불·선인장
- 다른 LivingEntity 점유
- 공격자 AABB에서 충분히 벗어나지 못함

백 회피에는 카운터 공격이 없다.

### 5.5 대형 몹 대각선 회피·카운터

#### 5.5.1 대상 분류

초기 기준:

```text
attacker horizontal width >= 0.90블록
→ 대각선 회피 후보
```

예:

- 워든
- 철 골렘
- 기타 실제 수평 히트박스가 큰 근접 Mob

특정 모드 몹도 실제 AABB 기준으로 분류한다.

#### 5.5.2 목적지

공격자 기준 좌후방·우후방 후보를 검사한다.

필수 조건:

- 워든걸 착지 AABB와 공격자 AABB가 겹치지 않음
- 궤적이 막히지 않음
- 안전한 바닥·머리 공간
- 위험 지형 없음
- 카운터 타격 틱에 일반 근접 사거리 유지 가능

안전성이 우선이다. 카운터 사거리를 유지할 수 없어도 안전한 회피가 가능하면 이동은 완료하고 카운터 피해만 생략할 수 있다.

#### 5.5.3 동작

```text
큰 근접 공격 피해 취소
→ 바닥을 강하게 박차며 대각선으로 튀어 오름
→ 공격자의 정면 공격선을 비껴감
→ 상체를 공격자 쪽으로 비틀며 타격
→ 공격자 측면·측후방에 착지
```

빠르게 달려가는 모션이 아니라 즉각적으로 몸이 떠오르는 회피 도약이어야 한다.

초기 대각선 목표 거리는 **2.5블록 전후**다.

#### 5.5.4 카운터 피해

- 현재 워든걸의 일반 근접 공격력 1회
- `test attack_damage` override 적용
- 소닉 피해 사용 안 함
- 광역 피해 없음
- 한 회피에 최대 1회
- 공격 모션의 실제 접촉 틱에 적용
- 공격자 생존·거리·시야·관계 필터를 타격 틱에 재검사
- 카운터는 기존 일반 근접 공격 간격과 공유해 즉시 일반 공격이 중복되지 않게 함

초기 목표 타격 시점은 도약 시작 후 **2~4틱 사이**다. 정확한 틱은 애니메이션의 손·팔 접촉 프레임과 맞춘다.

### 5.6 플레이어 조준선 회피

#### 5.6.1 대상

현재 유효한 전투 target이 Player일 때 그 플레이어 한 명의 시선만 검사한다.

- 주변 모든 플레이어의 시선을 합산하지 않음
- target이 아닌 플레이어는 적극적 조준 회피 대상으로 삼지 않음
- 다른 플레이어가 쏜 실제 화살은 일반 사이드홉으로 처리 가능

#### 5.6.2 조준 판정

플레이어 눈 위치와 look vector로 만든 ray가 워든걸의 현재 또는 짧은 예상 AABB를 향하는지 검사한다.

초기 기준:

```text
검사 간격        : 2틱
조준 유지 요구   : 6틱
회피 방향 유지   : 8~14틱
최소 방향 유지   : 8틱
```

정확한 ray-AABB 계산을 사용하며 단순 yaw 차이만 사용하지 않는다.

#### 5.6.3 움직임

조준선 안에 계속 머무르지 않도록 좌·우·전방 대각선 중 안전한 방향을 선택한다.

- 공격 대상에 대한 압박 유지
- 거리를 무의미하게 크게 벌리지 않음
- 한 방향을 고르면 최소 유지 시간 동안 유지
- 매 틱 좌우를 뒤집지 않음
- 최근 방향에 약한 반복 패널티
- 안전하지 않으면 정상 추격
- 회피 목적지 때문에 절벽에 빠지지 않음

이 행동은 공격을 반드시 무효화하지 않는다. 플레이어가 다시 조준하거나 넓게 휘두르면 맞을 수 있다.

#### 5.6.4 자연스러움

금지:

- 매 틱 좌우 반전
- 제자리에서 부들부들 떨기
- 여러 플레이어 사이의 가상 안전점 찾기
- 플레이어 시선이 조금 움직일 때마다 즉시 방향 재선택

목표 표현:

```text
조준당함
→ 한쪽 대각선으로 몇 틱 파고듦
→ 정상 공격 접근
→ 다시 명확히 조준당하면 새 방향 선택
```

### 5.7 플레이어 근접 대각선 패링·카운터

플레이어의 직접 근접 공격이 실제로 워든걸에 적용되려 할 때, 플레이어 폭과 무관하게 대각선 회피 규칙을 사용한다.

- 기본 확률 20%
- 피해·붉은 점멸·hurt 모션 취소
- 플레이어 AABB와 겹치지 않는 좌후방·우후방으로 도약
- 이동 중 현재 근접 공격력 1회 카운터
- 안전 후보가 없으면 정상 피격
- 공중·다른 회피 중이면 정상 피격
- 시간 쿨다운 없음

`test attack_damage set ... 0`을 사용하면 카운터와 일반 공격 모션을 체력 손실 없이 관찰할 수 있다.

### 5.8 처리하지 않는 피해

확률 회피는 다음 피해를 취소하지 않는다.

- 투사체가 실제로 맞은 피해
- 소닉붐
- 폭발
- 마법
- 화염
- 낙하
- 환경 피해
- 즉발 광선
- 공격자를 신뢰성 있게 식별할 수 없는 피해
- 근접 공격처럼 보이지만 실제로는 범위 DamageSource인 모드 공격

## Part 6. 행동 우선순위와 상태 충돌

### 6.1 의미상 우선순위

```text
1. 기존 저체력 FLEE 목적 유지
2. 이미 실행 중인 공중·벽 하강 특수 이동
3. 실제 근접 피격 순간의 확률 회피 판정
4. 임박한 단일 투사체 사이드홉
5. 기존 소닉·근접 공격의 확정 행동
6. 플레이어 조준선 회피 이동
7. 기존 전투 추격·소유자 추종·FLEE navigation
8. 목적지 경로의 지형 특수 이동
9. 일반 생활·배회
```

FLEE가 목적지를 정하고 지형 이동은 그 목적지를 향하는 수단이다.

### 6.2 사이드홉과 플레이어 조준 회피

실제 충돌 예정 투사체가 있으면 사이드홉이 우선한다.

사이드홉 착지 후 플레이어 조준 회피 방향을 다시 계산한다.

### 6.3 근접 회피와 기존 공격

피격 순간 성공한 백·대각선 회피는 현재 일반 근접 공격 준비보다 우선한다.

- 백 회피는 현재 근접 공격을 취소하고 거리 확보
- 대각선 카운터는 기존 일반 공격을 카운터 공격으로 대체
- 카운터 후 기존 19틱 근접 간격과 중복 타격이 발생하지 않게 공유 상태 갱신

### 6.4 소닉 중 회피

- 공중이 아닌 지상 소닉 충전 중 사이드홉은 상체 소닉 표현을 유지할 수 있을 때만 허용
- 근접 피해가 실제 들어오면 기존 T21/T12.5 규칙과 충돌하지 않도록 현재 소닉 취소 여부를 확인
- 공중 다이브·벽 박차기·벽 하강 중에는 새 회피 없음

구현 전에 현재 소닉 컨트롤러 우선순위를 확인하며, 회피 때문에 소닉 피해가 이중 방출되거나 age가 재시작되지 않아야 한다.

## Part 7. 애니메이션·동기화 원칙

### 7.1 새 애니메이션 후보

필수 새 동작:

```text
gap_dive_prepare / gap_dive_air / gap_dive_land
wall_rebound_runup / wall_rebound_contact / wall_rebound_land
wall_descent_grip / wall_descent_release
side_hop
back_dodge
diagonal_counter
```

실제 파일 분할은 현재 GeckoLib 컨트롤러 구조를 확인한 뒤 최소 클립 수로 정한다. 한 클립을 phase 값과 속도로 재사용할 수 있으면 중복 파일을 만들지 않는다.

### 7.2 새 애니메이션이 없는 동작

- 유격 1~3 일반 점프
- 피해 없는 짧은 낙하
- edge brake
- route resume
- 플레이어 조준선 회피의 기본 지상 이동

플레이어 조준 회피는 기존 보행·달리기와 실제 이동 방향으로 표현한다. 필요하지 않은 별도 좌우 떨림 클립을 만들지 않는다.

### 7.3 상체·하체 합성

- 사이드홉 중 머리·상체는 현재 target을 가능한 범위에서 추적
- 대각선 카운터는 상체 타격과 하체 도약을 같은 동작으로 맞춤
- 벽 하강 중 몸은 벽 방향, 머리는 제한적으로 독립
- 기존 소닉 상체와 회피 하체가 함께 필요한 경우 T21.5 구조를 재사용

### 7.4 네트워크

서버가 동작 종류·방향·시작 tick·필요한 목표 위치를 확정한다.

불필요한 매 tick 커스텀 패킷을 만들지 않는다. 기존 entity position/delta sync와 최소 `SynchedEntityData` 또는 entity event로 표현 가능한지 먼저 검토한다.

두 클라이언트에서 다음이 일치해야 한다.

- 회피 방향

#### [기계 검증]

1. 철 골렘·워든 폭에서 대각선 분류

6. attack override 0에서 카운터 피해 0

### T37 — 플레이어 조준선 회피와 대각선 패링

#### 검증 명령

/wardengirl test attack_damage clear @e[type=wardengirl:warden_girl,sort=nearest,limit=1,distance=..32]

- 플레이어의 긴 근접 공격을 대각선으로 패링하고 반격하는 느낌이 나는가

## Part 9. 구현 순서 요약

```text
T27 검증 명령
→ T28 공통 이동 기반
→ T29 유격 1~3 일반 점프
→ T30 유격 4~5 다이브
→ T31 2블록 벽 박차기
→ T32 짧은 낙하·절벽 정지
→ T33 벽 매달림 하강
→ T34 투사체 사이드홉
→ T35 소형 근접 백 회피
→ T36 대형 근접 대각선 카운터
→ T37 플레이어 조준 회피·패링
→ T38 전체 통합
```

이 순서를 바꾸지 않는다.

- 명령과 상태 기반이 먼저 있어야 후속 기능을 독립 검증할 수 있다.
- 일반 지형 이동을 먼저 고정해야 전투 회피 목적지 안전 검사가 같은 규칙을 재사용할 수 있다.
- 피해 취소가 없는 사이드홉을 먼저 만든 뒤 실제 피해 취소 회피를 구현한다.
- 플레이어 전투는 투사체·대각선 카운터 기반이 확정된 뒤 마지막에 결합한다.

## Part 11. 4차 최종 완료 정의

4차 완료는 다음을 모두 만족한 상태다.

1. 워든걸이 유격 1~3블록을 새 애니메이션 없이 일반 점프로 넘는다.
2. 유격 4~5블록은 멈춰 준비한 뒤 다이브하고, 6블록 이상은 거절한다.
3. 정확히 2블록 벽만 팔·발 반동으로 빠르게 넘으며 기어오르지 않는다.
4. 피해 없는 단차는 내려가고, 다른 안전 수단이 없는 위험 절벽에서는 멈춘다.
5. 피해가 생기는 높은 벽에서 팔다리와 가루 파티클로 매달려 내려오고 안전 높이에서 손을 놓는다.
6. 벽 하강 중 접촉을 잃으면 그 높이부터 정상 낙하 피해를 계산한다.
7. 지상 정지·걷기·달리기 중 실제 충돌할 단일 투사체를 자연스럽게 사이드홉한다.
8. 소형 근접 공격은 25% 백 회피, 대형 근접 공격은 20% 대각선 카운터를 사용한다.
9. 회피에는 시간 쿨다운이 없지만 공중·동작 중 재발동하지 않는다.
10. 플레이어와 전투할 때 현재 대상의 조준선을 떨림 없이 피하려 노력한다.
11. 플레이어 근접 피격은 20% 대각선 패링·카운터 후보가 된다.
12. 물 낙하와 포션 회피는 존재하지 않는다.
13. 모든 핵심 판정은 서버 권위이며 두 실제 클라이언트에서 결과가 일치한다.
14. 기존 1~3차 기능에 회귀가 없다.
15. 각 태스크가 문서의 독립 검증 명령과 측정 결과로 확인됐다.
