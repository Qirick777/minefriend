# 워든걸 2차 설계서

- 문서 상태: 2차 기본 기능 설계안
- 작성 기준일: 2026-07-30
- 대상 환경: Minecraft 1.20.1 / Forge 47.4.10 / GeckoLib 4.8.4
- 적용 대상: `WardenGirl` 엔티티
- 범위: 기본 스탯, 개체별 성장, 소유권, 추종·자율행동, 소유자 전투 지원, 화염 면역, 소닉붐 피해·범위화

---

## 1. 문서 목적

이 문서는 1차 설계에서 완성한 외형·모션·기본 전투 동작 위에, 워든걸을 실제 동료 개체로 사용할 수 있도록 만드는 2차 기본 기능을 정의한다.

2차 설계의 핵심 목표는 다음과 같다.

1. 모든 성장과 소유권이 개체별로 독립적일 것
2. 멀티플레이 서버를 기준으로 정확하게 동작할 것
3. 길들여진 뒤에도 자율행동을 유지할 것
4. 명령어가 없어도 기능 자체가 존재하도록 내부 API를 먼저 설계할 것
5. 기존 1차 기능과 애니메이션을 훼손하지 않을 것
6. 이후 길들이기 상호작용과 강화 상호작용을 쉽게 연결할 수 있을 것

---

## 2. 구현 원칙과 코더의 재량권

### 2.1 기본 원칙

코더는 본 설계의 기능적 의도와 확정된 게임 규칙을 따라 구현한다. 다만 문서를 기계적으로 복사하는 것이 목적은 아니다.

다음과 같은 확실한 문제가 발견되면 즉시 구현하지 않고 반려·질문·대안을 제시할 수 있다.

- Minecraft 1.20.1 또는 Forge 47.4.10의 실제 코드 구조와 충돌
- 데이터 손상, 저장 중복, Attribute 누적 가능성
- 서버·클라이언트 불일치 또는 멀티플레이 오작동 가능성
- 기존 1차 기능의 명확한 회귀 가능성
- 요구 효과에 비해 지나치게 무거운 구조가 필요한 경우
- 동일 결과를 훨씬 단순하고 안전하게 만들 수 있는 방법이 있는 경우
- 바닐라 워든 동작과 설계 전제가 실제로 다를 경우

### 2.2 반려·질문 시 의무

코더는 단순히 “어렵다”라고 말해서는 안 된다. 다음을 짧고 분명하게 보고한다.

1. 문제가 되는 정확한 코드 또는 엔진 구조
2. 실제 발생 가능한 실패 상황
3. 설계 의도를 유지하는 최소 대안
4. 대안별 난이도와 변경 범위
5. 사용자 승인이 필요한 결정점

### 2.3 코더가 자율적으로 결정할 수 있는 범위

다음은 기능 의미를 바꾸지 않는 한 코더가 결정할 수 있다.

- 클래스·메서드·필드 이름
- 파일 배치
- Goal 분리 방식
- 공통 유틸리티 구성
- NBT 키 이름
- 캐시 사용 여부
- 테스트 하네스 구성
- 수치 계산을 위한 내부 함수 분리
- 불필요한 중복을 없애는 리팩터링

### 2.4 사용자 승인이 필요한 범위

다음은 임의로 변경하지 않는다.

- 기본 스탯과 성장 기준
- 성장 천장
- 소유권 변경 가능 여부
- 소유자 및 같은 소유자 워든걸의 면역 범위
- 추종 순간이동 금지
- 소닉붐의 범위공격 여부
- 화염 면역 여부
- 전투 대상 의미
- 외형과 애니메이션의 육안 품질 판단

### 2.5 검증 역할

- 코드·수치·서버 판정·동기화는 코더가 증거로 검증한다.
- 자연스러움·귀여움·시각적 완성도는 사용자가 직접 판단한다.
- 실제 두 클라이언트 시험 전에는 멀티플레이 완료로 선언하지 않는다.

## 3. 설계 핵심 규칙

### 3.1 서버 정본

소유권, 강화 스택, 스탯, 공격 대상, 피해, 넉백 판정은 서버가 결정한다.

클라이언트는 서버가 결정한 엔티티 상태와 기존 엔티티 동기화를 렌더링한다. 현재 화면을 보고 있는 로컬 플레이어를 소유자로 간주하는 방식은 금지한다.

### 3.2 개체별 독립성

각 워든걸은 독립적으로 다음 데이터를 가진다.

- 소유자 UUID 또는 없음
- 강화 스택
- 계산된 최대 체력
- 계산된 근접 공격력
- 계산된 소닉붐 피해
- 계산된 밀치기 저항

전역 static 성장값, 공용 현재 스택, 엔티티 타입 전체의 기본 Attribute를 런타임에 바꾸는 방식은 금지한다.

### 3.3 명령어 비종속 구조

명령어는 개발·검증을 위한 진입점일 뿐이다.

핵심 기능은 다음과 같은 개체 API로 먼저 존재해야 한다.

```java
Optional<UUID> getOwnerUuid();
boolean hasOwner();
boolean trySetInitialOwner(UUID ownerUuid);
long getPowerStacks();
void setPowerStacks(long stacks);
void addPowerStacks(long amount);
void recalculatePowerStats(boolean healGrowthDelta);
double getSonicDamage();
```

향후 길들이기 아이템·상호작용은 `trySetInitialOwner`를 호출하고, 강화 아이템·상호작용은 `addPowerStacks`를 호출한다.

## 4. 소유권 설계

### 4.1 길들여짐의 정의

별도의 `tamed` boolean은 두지 않는다.

```text
owner UUID 없음 = 야생
owner UUID 있음 = 길들여짐
```

### 4.2 최초 각인

- 워든걸은 최초 한 번만 특정 플레이어 UUID에 각인된다.
- 정상 게임 기능으로 소유권 변경·해제·이전은 제공하지 않는다.
- 소유자가 오프라인이거나 다른 차원에 있어도 다른 플레이어를 대신 소유자로 선택하지 않는다.
- 플레이어 이름이 아니라 UUID를 저장한다.
- 소유자 UUID는 해당 워든걸의 NBT에 저장한다.

### 4.3 소유 관계 공통 판정

소유자 보호와 같은 소유자의 워든걸 판정은 한 공통 함수로 모은다.

```java
boolean isOwnerOrSameOwnerWardenGirl(Entity target);
```

의미:

- 대상이 이 워든걸의 소유자면 `true`
- 대상이 워든걸이고 양쪽 owner UUID가 같으면 `true`
- owner UUID가 없는 야생 워든걸끼리는 같은 소유자로 취급하지 않음

이 판정은 목표 선정, 근접 공격, 소닉붐 피해, 소닉붐 넉백, 복수 목표 선정에서 재사용한다.

## 5. 기본 스탯과 화염 면역

### 5.1 0스택 기본값

| 항목 | 값 |
|---|---:|
| 최대 체력 | 30 |
| 근접 공격력 | 7 |
| 소닉붐 피해 | 5 |
| 밀치기 저항 | 0% |
| 기본 이동속도 Attribute | 기존 0.23 유지 |
| 근접 추적 navigation 배율 | 1.3D |

### 5.2 화염 면역

워든걸은 화염 피해를 입지 않는다.

- 불
- 용암
- 불타는 상태
- 화염 속성 공격
- 기타 Minecraft 1.20.1에서 화염 피해 태그로 분류되는 피해

개별 DamageSource 이름을 나열하기보다 해당 버전의 화염 피해 태그 또는 바닐라 화염 면역 경로를 우선 사용한다.

화염 피해만 막고 일반 피해, 마법 피해, 폭발 피해까지 함께 막아서는 안 된다.

## 6. 개체별 강화 스택

### 6.1 저장 형식

- 개체별 비음수 정수
- NBT에 저장
- 권장 저장형: `long`
- 음수 입력은 0으로 보정하거나 거절
- 한 개체의 스택 변경은 다른 워든걸에 영향을 주지 않음

`long`의 기술적 한계는 존재하지만, 게임 설계상 스택 상한은 두지 않는다. 스탯은 수렴식으로 계산하므로 큰 스택에서도 안전하게 천장에 가까워진다.

### 6.2 0~100스택 선형 성장

스택을 `s`라고 할 때 `0 ≤ s ≤ 100`:

```text
최대 체력 = 30 + 4.7 × s
근접 공격력 = 7 + 0.38 × s
소닉붐 피해 = 5 + 0.10 × s
밀치기 저항 = 0.01 × s
```

100스택에서 정확히 다음 값이 된다.

| 항목 | 100스택 값 |
|---|---:|
| 최대 체력 | 500 |
| 근접 공격력 | 45 |
| 소닉붐 피해 | 15 |
| 밀치기 저항 | 100% |

### 6.3 100스택 초과 감쇠 성장

100스택 이후에도 스택은 계속 증가하지만 스탯 증가량은 점차 감쇠한다.

이론적 성장 천장:

| 항목 | 도달 불가능한 천장 |
|---|---:|
| 최대 체력 | 1020 |
| 근접 공격력 | 100 |
| 소닉붐 피해 | 30 |
| 밀치기 저항 | 100% |

1020, 100, 30은 수학적 극한이다. 스택이 무한히 증가해도 해당 값을 넘지 않으며 이론상 정확히 도달하지 않는다.

`x = s - 100`일 때:

```text
최대 체력 = 1020 - 520 × e^(-x / 150)
근접 공격력 = 100 - 55 × e^(-x / 150)
소닉붐 피해 = 30 - 15 × e^(-x / 150)
밀치기 저항 = 1.0
```

대표값:

| 스택 | 최대 체력 | 근접 | 소닉 |
|---:|---:|---:|---:|
| 0 | 30.0 | 7.0 | 5.0 |
| 50 | 265.0 | 26.0 | 10.0 |
| 100 | 500.0 | 45.0 | 15.0 |
| 200 | 약 753.0 | 약 71.8 | 약 22.3 |
| 300 | 약 882.9 | 약 85.5 | 약 26.0 |
| 500 | 약 983.9 | 약 96.2 | 약 29.0 |
| 1000 | 약 1018.7 | 약 99.9 | 30에 매우 근접 |

부동소수점 반올림으로 천장과 정확히 같아지는 경우를 막기 위해 구현에서는 각 천장의 `Math.nextDown(cap)` 이하로 제한한다.

### 6.4 강화 시 체력 회복

실제로 스택이 증가해 최대 체력이 늘어난 경우:

```text
현재 체력 += 새 최대 체력 - 이전 최대 체력
```

최대 체력 증가량만큼만 회복한다.

예:

```text
강화 전 18 / 30
최대 체력 +4.7
강화 후 22.7 / 34.7
```

다음 상황에서는 회복하지 않는다.

- 청크 재로드
- 서버 재시작
- 엔티티 NBT 로드
- 동일 스택으로 재계산
- Attribute 복구 호출

### 6.5 멱등 스탯 재계산

`recalculatePowerStats`는 몇 번 호출해도 같은 스택에서 같은 결과를 내야 한다.

- modifier를 반복 추가하지 않음
- 개체 AttributeInstance의 목표 base value를 정확히 설정
- 기존 일시적 포션·장비 modifier는 별도 레이어로 유지
- 다른 워든걸의 Attribute에 영향 없음
- 소닉 피해는 발사 개체의 스택에서 계산

## 7. 길들여진 워든걸의 생활 행동

### 7.1 행동 목표

길들여진 워든걸은 소유자 뒤에 붙어 있기만 하는 애완동물이 아니다.

소유자 주변에서 기존 자율행동과 배회를 유지하고, 거리가 벌어질 때만 추종한다. 순간이동은 사용하지 않는다.

### 7.2 거리 규칙

| 상태 | 소유자와의 거리 |
|---|---:|
| 소유자 주변 자율 배회 중심 반경 | 8블록 |
| 일반 추종 시작 | 12블록 초과 |
| 일반 추종 종료 | 8블록 이하 |
| 빠른 추종 시작 | 20블록 초과 |
| 빠른 추종 해제 | 16블록 이하 |
| 추종 완전 포기 | 48블록 초과 |
| 포기 후 현지 배회 반경 | 10블록 |
| 소유자 재합류 인식 | 24블록 이내 |

서로 다른 시작·종료 거리를 사용해 Goal이 경계에서 반복적으로 켜지고 꺼지는 현상을 막는다.

### 7.3 추종 속도

- 일반 추종: `1.0D`
- 빠른 추종: `1.3D`
- 빠른 추종에서는 1차 설계에서 확정한 달리기 표현을 자동 재사용
- 이동속도 Attribute 자체를 소유자 추종 때문에 영구 변경하지 않음

### 7.4 추종 포기와 현지 배회

소유자가 48블록보다 멀어지면 무한히 따라가지 않는다.

- 현재 추종 Goal 중단
- 포기 시점의 현재 위치를 임시 생활 중심점으로 설정
- 그 위치 반경 10블록에서 배회·대기·시선·킁킁 등 기존 자율행동 유지
- 소유자의 마지막 위치로 무한 경로 탐색하지 않음
- 순간이동 금지
- 강제 청크 로딩 금지

소유자가 같은 차원에서 24블록 이내로 돌아오고 정상 경로를 만들 수 있으면 소유자 중심 행동을 재개한다.

### 7.5 소유자 부재

다음 상황에서는 현재 위치에서 자율행동한다.

- 소유자가 오프라인
- 소유자가 다른 차원
- 소유자 엔티티를 서버가 찾을 수 없음
- 소유자까지 경로가 장시간 생성되지 않음
- 추종 포기 거리 초과

## 8. 소유자 전투 지원

### 8.1 지원 대상

길들여진 워든걸은 다음 대상을 공격한다.

1. 소유자가 최근 직접 공격한 유효 대상
2. 최근 소유자를 공격한 유효 대상

### 8.2 기록 유효시간

소유자의 최근 공격·피격 기록은 200틱, 즉 10초까지만 유효하게 사용한다.

오래된 대상을 무한 추격하지 않는다.

### 8.3 공통 대상 필터

다음 대상은 공격하지 않는다.

- 소유자 본인
- 같은 owner UUID를 가진 다른 워든걸
- 죽었거나 제거된 엔티티
- 다른 차원에 있는 엔티티
- 현재 게임 규칙상 공격할 수 없는 플레이어
- 정상적인 `canAttack` 또는 동맹 판정에서 거절되는 대상
- 너무 오래된 공격 기록의 대상

투사체나 간접 피해는 실제 공격자·소유자를 추적할 수 있는 범위에서 판정한다.

### 8.4 같은 소유자의 워든걸 사이

- 같은 소유자의 워든걸끼리는 일반 공격 대상이 아님
- 한 워든걸이 같은 소유자의 다른 워든걸을 우발적으로 공격해도 집단 보복하지 않음
- 같은 소유자의 다른 워든걸은 소닉붐 피해와 넉백에도 면역

다른 동물, 늑대, 고양이, 팀 플레이어는 이 설계에서 추가 아군으로 취급하지 않는다.

### 8.5 행동 우선순위

```text
현재 전투
→ 소유자 전투 지원
→ 소유자 추종
→ 소유자 주변 또는 현지 자율 배회
→ 일반 대기 행동
```

현재 전투가 끝난 뒤 소유자 중심 또는 현지 생활 중심으로 복귀한다.

## 9. 소닉붐 피해와 범위공격

### 9.1 바닐라 워든 기반 요소

다음 요소는 Minecraft 1.20.1 바닐라 워든 소닉붐 구현을 직접 확인한 뒤 가능한 한 그대로 사용한다.

- 발사점
- 목표 방향
- 빔 길이
- 파티클 진행
- 소리
- 사거리
- 넉백 방향과 방식
- 블록과의 상호작용
- DamageSource 성격

현재 T8의 확정된 시간 구조는 유지한다.

- 총 60틱
- 방출 34틱
- 수평 탐색 15블록
- 수직 탐색 20블록
- 소닉 쿨다운 100틱

바닐라 코드와 현재 전제가 다르면 코더는 임의 구현하지 않고 실제 차이를 보고한다.

### 9.2 워든걸 전용 범위공격

바닐라 워든의 소닉붐은 단일 대상 공격이지만 워든걸은 범위공격으로 확장한다.

- 하나의 주 목표를 향해 발사
- 발사점과 목표 지점을 잇는 선분을 중심으로 판정
- 판정 형태: 캡슐형 범위
- 판정 반경: 1.0블록
- 범위 안의 유효한 LivingEntity를 서버에서 수집
- 한 번의 소닉붐에서 각 개체는 최대 한 번만 피격
- 첫 개체를 맞아도 빔이 중단되지 않음
- 거리별 피해 감소 없음
- 의도하지 않은 동물·몬스터·다른 플레이어도 범위 안에 있으면 오인사격 피해 가능

### 9.3 소닉붐 피해

소닉붐 피해는 발사한 워든걸의 개체별 강화 스택으로 계산한다.

```java
double damage = attacker.getSonicDamage();
```

전역 현재 피해값이나 공용 static 값을 사용하지 않는다.

### 9.4 소유자 면역

다음 대상은 소닉붐 피해와 넉백을 모두 받지 않는다.

- 발사 워든걸의 소유자
- 같은 owner UUID를 가진 다른 워든걸

면역 대상이 빔 범위 안에 있어도:

- 파티클은 통과 가능
- 피해 없음
- 넉백 없음
- 뒤쪽 다른 대상의 피격을 차단하지 않음

최종 피해·넉백 적용 직전에 공통 소유 관계 필터를 다시 검사한다.

## 10. 개발·검증용 명령어

명령어는 핵심 로직을 직접 구현하지 않고 개체 API만 호출한다.

권장 기능:

```text
/wardengirl owner set <entity> <player>
/wardengirl power get <entity>
/wardengirl power set <entity> <stacks>
/wardengirl power add <entity> <amount>
/wardengirl stats get <entity>
```

### 10.1 소유자 명령 규칙

- `owner set`은 owner UUID가 없는 개체에만 성공
- 이미 owner UUID가 있으면 거절
- 일반 명령으로 변경·해제하지 않음
- 명령어 제거 후에도 `trySetInitialOwner` API는 유지

### 10.2 스택 명령 규칙

- 개체별로만 적용
- 음수 결과 금지
- `set`과 `add` 모두 동일한 스탯 재계산 함수를 호출
- 실제 증가분이 있을 때만 최대 체력 증가량만큼 회복
- 감소 테스트 시 현재 체력이 새 최대 체력을 넘으면 새 최대 체력으로 제한

## 11. 저장·동기화

### 11.1 NBT 저장

최소 저장값:

```text
OwnerUUID: UUID, 선택
PowerStacks: long
```

계산 가능한 스탯 결과를 중복 저장하지 않는다. 로드 시 스택으로 재계산한다.

### 11.2 클라이언트 동기화

현재 설계에서는 owner UUID와 power stack을 렌더링에 직접 쓰지 않는다. 따라서 서버 로직만으로 충분하면 불필요한 SynchedEntityData를 추가하지 않는다.

향후 UI·이름표·외형 변화에서 클라이언트 값이 필요해질 때 별도 동기화를 추가한다.

### 11.3 로드 순서

- NBT에서 owner UUID와 power stack 읽기
- 서버에서 스탯 멱등 재계산
- 기존 저장 체력 유지
- 재계산 때문에 추가 회복하지 않음
- 현재 체력이 최대 체력을 넘으면 최대 체력으로 제한

#### 이유

공간 판정, 중복 피격, 아군 예외가 함께 들어가는 고위험 기능이므로 기본 소닉 피해와 분리한다.

#### 완료 기준

- 동일 개체 중복 피격 없음
- 빔 옆 경계 판정 수치 확인
- 소유자·같은 소유자 피해·넉백 0
- 다른 개체는 오인사격 가능
- 서버와 두 클라이언트가 같은 피격 결과 관찰

## 14. 추후 설계로 남기는 항목

다음은 2차 기반에 연결할 수 있도록 API만 열어두고, 이번 설계에서 획득 방식을 정하지 않는다.

- 실제 길들이기 아이템 또는 상호작용
- 길들이기 성공 조건
- 강화 재료 또는 강화 상호작용
- 강화 비용과 횟수 제한
- 스택 표시 UI
- 소유자 전용 상호작용 메뉴
- 앉기·대기 명령
- 소유권 해제·이전 기능
- 팀·파티·다른 애완동물까지 확장한 아군 판정

이 항목을 미리 추측해 구현하지 않는다.

## 15. 금지 사항

- 싱글플레이 현재 플레이어에 의존한 소유자 판정
- 모든 워든걸이 공유하는 owner 또는 stack
- 전역 static 현재 스탯
- 성장 때 엔티티 타입 전체 Attribute 변경
- 재로드마다 modifier 누적
- 재로드마다 체력 회복
- 늑대·고양이식 순간이동 추종
- 강제 청크 로딩
- 길들여진 뒤 자율행동 제거
- 소유자에게 소닉붐 피해 또는 넉백 적용
- 같은 소유자의 워든걸끼리 공격·복수
- 명령어 안에 핵심 기능을 직접 구현
- 사용자 승인 없이 길들이기·강화 획득 방식 발명
- 사용자 승인 없이 설계 핵심 수치 변경

## 16. 최종 설계 요약

- owner UUID가 있으면 길들여짐, 없으면 야생
- owner는 최초 각인 후 변경·해제 없음
- 강화 스택은 개체별 `long`
- 0스택: 체력 30 / 근접 7 / 소닉 5 / 밀치기 저항 0%
- 100스택: 체력 500 / 근접 45 / 소닉 15 / 밀치기 저항 100%
- 100스택 이후 감쇠 성장
- 도달 불가능한 천장: 체력 1020 / 근접 100 / 소닉 30
- 실제 강화 시 최대 체력 증가량만큼 회복
- 화염 피해 면역
- 소유자 주변에서 자율 배회
- 일반 추종 12→8, 빠른 추종 20→16
- 48블록 초과 시 추종 포기 후 현지 배회
- 순간이동 없음
- 소유자가 공격한 대상과 소유자를 공격한 대상을 200틱 동안 지원
- 소유자와 같은 소유자의 워든걸은 일반 공격 대상이 아님
- 소닉붐은 워든 기반 외형·넉백을 사용하되 반경 1.0 캡슐 범위공격
- 소유자와 같은 소유자의 워든걸은 소닉 피해·넉백 완전 면역
- 길들이기와 강화의 실제 상호작용 방식은 후속 설계
- 코더는 확실한 위험이 있을 때 반려·질문·대안을 제시할 권한과 의무가 있음
