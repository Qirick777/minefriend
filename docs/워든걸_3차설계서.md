**환경:** Minecraft 1.20.1 / Forge 47.4.10 / Java 17 / official mappings / GeckoLib 4.8.4  
**기준 구현:** 2차 완료 상태 `42bd5df`  
**태스크 연속성:** 2차 설계서의 마지막 태스크 `T18` 다음인 `T19`부터 시작

## Part 0. 구현자 준수사항

이 문서를 읽는 구현자(Claude Code)는 다음을 반드시 지킨다.

1. **Part 4의 확정 수치를 임의로 바꾸지 않는다.** 수치가 실제 플레이에서 부적절하다고 판단되면 수정하지 말고 측정값과 함께 보고한다.
2. **문서에 없는 기능을 추가하지 않는다.** 적대 몹 목록, 순간이동, 업고 도망가기, 머리 탑승, 청크 강제 로딩 등을 임의로 도입하지 않는다.

4. **한 태스크를 완료했다고 다음 태스크로 자동 진행하지 않는다.**
5. **현재 코드와 Minecraft 1.20.1 공식 매핑을 먼저 확인한다.** API 이름이나 바닐라 동작을 기억으로 추정하지 않는다.

9. **현재 소유자 UUID 구조를 유지한다.** 전역 소유자 관리자, 현재 접속 플레이어 가정, 로컬 플레이어 가정을 만들지 않는다.

11. **T15의 중립 전투 구조를 유지한다.** 주변 몬스터를 종류만 보고 선제 공격하지 않는다.

## Part 1. 프로젝트 정의

### 1.1 3차에서 무엇을 만드는가

2차까지의 워든걸은 소유자를 따라다니며, 자신이나 소유자가 실제로 공격받은 후 반격하는 중립 동료다.

3차에서는 이를 다음 단계로 확장한다.

| 축 | 내용 |
|---|---|
| **능동 경호** | 소유자를 실제 공격 대상으로 삼고 접근하는 적을 선제 차단 |
| **자기 보존** | 저체력일 때 근접전을 중단하고 소유자 주변에서 후퇴 |
| **후퇴 견제** | 안전하게 충전할 수 있을 때만 소닉붐으로 추격자 견제 |
| **회복** | 일정 시간 피해를 받지 않으면 서서히 체력 회복 |
| **생활 이동** | 나무문을 열고 통과하며 필요하면 다시 닫음 |
| **건물 진입** | 소유자가 문 안으로 들어가면 추종 거리와 무관하게 재결합 |
| **파수꾼** | 소유자가 침대에서 자는 동안 침대 주변에 앉아 경계 |

### 1.2 핵심 컨셉

**“싸울 때만 따라오는 전투 소환물이 아니라, 소유자와 같은 공간에서 생활하며 스스로 살아남는 경호 동료.”**

3차의 워든걸은 다음 세 가지를 동시에 만족해야 한다.

1. 소유자를 위협하는 적을 먼저 알아본다.
2. 죽을 상황에서는 무모하게 근접전을 계속하지 않는다.
3. 전투가 없을 때는 문을 통과하고, 집 안에 들어오며, 수면 중 소유자 곁을 지킨다.

### 1.3 중립성 유지

능동 경호는 무차별 선제 공격이 아니다.

다음 세 조건을 모두 만족하는 적만 자동 처리한다.

```text
소유자를 현재 공격 대상으로 삼음
AND
소유자에게 접근 가능한 실제 경로가 있음
AND
소유자 방어 반경 안에 들어옴
```

단순히 소유자 주변을 지나가는 몬스터, 다른 대상을 공격하는 몬스터, 벽 너머에서 소유자에게 접근할 수 없는 몬스터는 자동 처리하지 않는다.

### 1.4 이번 3차에서 제외하는 것

다음은 추후 별도 설계 대상으로 남긴다.

- 업고 도망가기
- 긴급 머리 탑승
- 일반 머리 탑승
- 워든걸이 소유자를 강제로 이동시키는 기능
- 소유자 대신 피해를 받는 기능
- 순간이동 추종
- 청크 강제 로딩
- 먹이·허기·아이템을 사용하는 회복
- 집이나 방을 의미적으로 인식하는 시스템
- 순찰 경로 지정
- 소유권 이전·해제·교체

## Part 2. 왜 3차를 이 순서로 분리하는가

### 2.1 능동 경호가 후퇴보다 먼저다

후퇴와 후퇴 중 소닉붐은 “현재 어떤 개체가 실제 위협인가”를 알아야 한다.

따라서 먼저 소유자에게 접근 중인 적을 정확하게 판정하는 기능을 확정한다. 이 판정이 불안정한 상태에서 후퇴를 만들면 평화로운 몹에게서 도망가거나 실제 위협을 무시할 수 있다.

### 2.2 후퇴 이동과 후퇴 소닉을 분리한다

후퇴 이동은 안전 지점을 찾는 문제이고, 후퇴 중 소닉은 충전 시간 안에 적이 도달하는지를 예측하는 문제다.

둘을 동시에 구현하면 다음 문제의 원인을 분리할 수 없다.

- 안전 지점 선택 실패
- navigation 실패
- 소닉 안전 판정 오류
- 소닉 충전 중 재검사 오류
- 근접 공격 Goal이 후퇴를 덮는 오류

따라서 후퇴 이동을 먼저 통과시킨 뒤 소닉을 허용한다.

### 2.3 문 통과와 문 재결합을 분리한다

문을 열고 닫는 기능과 “가까워도 문을 열고 소유자에게 들어가는 기능”은 서로 다른 문제다.

- 문 통과: navigation 경로에 놓인 문을 처리
- 문 재결합: 일반 추종 정지 거리 안에서도 문을 지나 소유자 쪽으로 이동

먼저 일반 경로에서 문을 정상적으로 통과하는지 확인한 후, 추종 거리 예외를 추가한다.

### 2.4 파수꾼은 마지막 생활 행동이다

파수꾼 행동은 다음 기능에 모두 의존한다.

- 소유자 확인
- 건물 내부 진입
- 문 통과
- 전투 우선순위
- 저체력 후퇴
- 전투 종료 후 상태 복귀

따라서 다른 생활·전투 상태가 확정된 뒤 구현한다.

### 2.5 페이즈 구성

| 페이즈 | 내용 | 주 판정자 |
|---|---|---|
| **1차** | 모델·애니메이션 구조와 전투 동작 | 사람의 눈 |
| **2차** | 소유권·성장·추종·중립 전투·소닉 피해 | 기계 검증 + 사람 확인 |
| **3차** | 능동 경호·생존·회복·문·건물 진입·파수꾼 | 기계 검증 + 사람 확인 |

| 상태 | 저장 | 이유 |

| 닫을 문 위치 | 저장하지 않음 | navigation 보조용 임시 상태 |
| 파수꾼 침대·대기 위치 | 저장하지 않음 | 소유자의 실제 수면 상태로 재계산 |

바닐라 `Pose.SITTING`을 현재 매핑과 렌더링 구조에서 재사용할 수 있는지 먼저 확인한다.

재사용할 수 있으면 별도 `SynchedEntityData`를 만들지 않는다. 사용할 수 없다면 파수꾼 착석 여부만 나타내는 동기화 boolean 하나를 허용한다.

### 3.4 새 전역 시스템 금지

다음을 만들지 않는다.

- 전역 위협 관리자
- 플레이어별 워든걸 목록 관리자
- 모든 몹의 경로를 저장하는 시스템
- 방 또는 집 인식 시스템
- 전역 문 사용 기록
- 별도 멀티플레이 동기화 관리자

모든 판단은 해당 워든걸 개체와 같은 서버 레벨에서 필요한 순간에만 수행한다.


## Part 4. 기능 상세

### 4.1 소유자 접근 적 자동 처리

#### 4.1.1 적용 대상

길들인 워든걸만 사용한다.

야생 워든걸은 기존처럼 다음 경우에만 싸운다.

- 자신을 공격한 대상
- 현재 유효한 기존 target

야생 워든걸은 플레이어를 대신 지키지 않는다.

#### 4.1.2 탐색 범위

```text
중심       : 유효한 소유자
수평 반경  : 16블록
수직 범위  : 위아래 8블록
검사 주기  : 10서버틱
```

서버에서 소유자 주변 AABB 안의 `Mob`만 후보로 조회한다.

#### 4.1.3 자동 처리 후보 조건

후보는 다음을 모두 만족해야 한다.

```text
후보가 살아 있음
AND
제거되지 않음
AND
소유자와 같은 서버 레벨
AND
후보.getTarget() == owner
AND
소유자 중심 수평 16블록·수직 8블록 안
AND
소유자에게 근접 경로로 도달 가능
AND
워든걸의 기존 isValidCombatTarget() 통과
AND
T14 전투 시작 leash 통과
```

후보가 이미 소유자의 근접 공격 거리 안에 있으면 경로 종점 여부와 무관하게 도달한 위협으로 인정한다.

#### 4.1.4 경로 판정

후보의 navigation을 이용해 소유자에게 향하는 `Path`를 생성한다.

```text
이미 소유자 근접 범위 안
→ 도달 가능

Path != null AND Path.canReach()
→ 도달 가능

그 외
→ 자동 처리 대상 아님
```

경로 probe는 후보의 실제 target이나 현재 navigation 이동 명령을 변경하지 않는다.

`moveTo()`를 호출해 성공 여부를 검사하지 않는다. 경로 생성 결과와 종점 도달 여부를 사용한다.

#### 4.1.5 대상 우선순위

기존 T15의 사건 기반 우선순위를 유지한다.

```text
1. 워든걸 자신을 최근 공격한 대상
2. 소유자를 최근 공격한 대상
3. 소유자가 최근 공격한 대상
4. 소유자를 공격 대상으로 삼고 접근 중인 자동 방어 대상
```

현재 target이 살아 있고 유효하며 T14 유지 leash 안이면 자동 방어 스캔 때문에 교체하지 않는다.

#### 4.1.6 후보가 여러 명인 경우

다음 순서로 선택한다.

```text
1. 소유자와의 수평 거리가 가장 가까운 후보
2. 경로 길이가 가장 짧은 후보
3. 동일하면 기존 선택 또는 엔티티 조회 순서 유지
```

매 검사마다 target을 흔드는 별도 점수 시스템을 만들지 않는다.

#### 4.1.7 자동 처리 종료

후보가 다음 상태가 되면 자동 방어 대상으로 유지하지 않는다.

- 소유자를 target으로 삼지 않음
- 사망·제거
- 다른 차원
- 소유자 반경 밖
- T14 전투 유지 leash 밖
- 공통 필터 실패

전투가 끝나면 기존 추종·현지 생활로 복귀한다.

### 4.2 저체력 후퇴

#### 4.2.1 진입과 해제

```text
후퇴 진입 : 현재 체력 ≤ 최대 체력의 25%
후퇴 해제 : 현재 체력 ≥ 최대 체력의 45%
```

경계값은 포함한다.

예:

| 최대 체력 | 진입 | 해제 |
|---:|---:|---:|
| 30 | 7.5 이하 | 13.5 이상 |
| 500 | 125 이하 | 225 이상 |
| 1000 | 250 이하 | 450 이상 |

25%와 45% 사이에서는 현재 후퇴 상태를 유지한다.

후퇴 상태는 NBT에 저장하지 않는다. 로드 후 현재 체력으로 다시 계산한다.

#### 4.2.2 행동 중심

유효한 소유자가 같은 서버 레벨에 있으면 소유자 위치를 중심으로 사용한다.

소유자가 다음 상태면 현재 워든걸 위치를 임시 중심으로 사용한다.

- 오프라인
- 다른 차원
- 죽음
- 제거
- 서버 레벨에서 확인 불가

대체 플레이어를 찾지 않는다.

#### 4.2.3 후퇴 범위

```text
중심                    : 소유자 또는 현재 위치 임시 중심
최대 후퇴 반경          : 12블록
선호하는 중심과의 거리 : 8~12블록
적과의 권장 최소 거리  : 8블록
```

소유자 중심 12블록 밖으로 무한 도주하지 않는다.

#### 4.2.4 후퇴 이동

```text
후퇴 이동속도 배율 : 1.6D
안전 지점 재평가   : 10서버틱
도착 판정          : 목표 1.5블록 이내
후보 수            : 최대 12개
```

바닐라 육상 임의 위치 탐색 API를 우선 재사용한다.

후보는 다음 조건을 만족해야 한다.

- 중심 반경 12블록 이내
- 고체 바닥
- 워든걸 충돌 공간 확보
- 불·용암·선인장·낭떠러지 등 명백한 위험 회피
- 실제 경로 생성 가능
- 현재 활성 위협들과 가능한 한 멀어짐

#### 4.2.5 안전 지점 평가 순서

```text
1. 가장 가까운 활성 위협과의 최소 거리가 큰 곳
2. 모든 활성 위협의 중심에서 멀어지는 곳
3. 소유자 중심 선호 거리 8~12 안
4. 경로 길이가 짧은 곳
5. 현재 위치에서 지나친 방향 전환이 적은 곳
```

완전한 안전 지점이 없으면 후보 중 가장 나은 지점을 사용한다.

경로가 없는 위치로 순간이동하지 않는다.

#### 4.2.6 후퇴 중 금지 행동

후퇴 상태에서는 다음을 금지한다.

- 근접 공격 시작
- 근접 공격 계속
- 적을 향한 추격 navigation
- 일반 소닉붐
- 일반 소유자 추종
- 일반 배회
- 파수꾼 착석

후퇴 진입 시 진행 중인 근접 공격과 소닉 충전을 중단하고 navigation을 정지한 후 안전 지점을 선택한다.

후퇴 중에도 target 자체는 위협 참조용으로 유지할 수 있다. 단, target을 향해 이동하지 않는다.

### 4.3 후퇴 중 안전한 소닉붐

#### 4.3.1 목적

후퇴 상태의 워든걸은 근접 공격하지 않는다.

다만 모든 실제 위협이 소닉 방출 시점까지 워든걸에게 닿을 수 없다고 판정될 때만 기존 소닉붐으로 견제한다.

#### 4.3.2 기본 조건

다음을 모두 만족해야 충전을 시작한다.

```text
후퇴 상태
AND
유효한 현재 target 존재
AND
target이 기존 소닉 사거리 안
AND
기존 소닉 cooldown 사용 가능
AND
T14 전투 leash 통과
AND
모든 활성 위협의 도달 예상 시간이 44틱 초과
```

44틱은 다음으로 구성된다.

```text
기존 방출까지 남은 시간 34틱
+
안전 여유 10틱
```

#### 4.3.3 활성 위협

다음 개체를 중복 없이 모은다.

- 현재 target
- 워든걸을 target으로 삼은 Mob
- 소유자를 target으로 삼은 Mob
- 워든걸의 현재 최근 공격자
- 소유자의 현재 최근 공격자

탐색 범위:

```text
워든걸 중심 수평 24블록
수직 위아래 12블록
```

현재 target과 최근 공격자는 범위 경계에 걸리더라도 별도로 검사한다.

활성 위협이 16개를 초과하면 안전한 충전으로 인정하지 않는다.

#### 4.3.4 경로 길이

위협에서 워든걸의 현재 위치까지 경로를 생성한다.

경로 길이는 다음을 합산한다.

- 위협 현재 위치에서 첫 노드까지 거리
- 각 경로 노드 사이 거리
- 마지막 노드에서 워든걸 근접 도달 지점까지 거리

이미 위협의 근접 공격 거리 안이면 예상 도달 시간은 0틱이다.

#### 4.3.5 예상 이동속도

보수적으로 다음 값을 사용한다.

```text
예상 블록/틱 =
max(
    0.10,
    위협의 현재 MOVEMENT_SPEED 속성 × 1.5
)
```

예상 도달 시간:

```text
예상 도달 틱 =
max(0, 경로 길이 - 위협의 근접 공격 도달 거리)
÷ 예상 블록/틱
```

소수점 결과는 아래로 버리지 않고 그대로 비교한다.

#### 4.3.6 경로가 없는 경우

다음처럼 구분한다.

```text
위협이 안정적인 지상 navigation 상태
AND
경로 계산을 정상 수행함
AND
Path == null 또는 canReach() == false
→ 현재 위치까지 근접 도달 불가
→ 안전한 위협으로 처리
```

다음은 판정 불가이므로 안전하지 않은 것으로 처리한다.

- 위협이 공중에 있음
- navigation이 현재 경로 계산을 수행할 수 없음
- 이동 방식이 육상 경로와 맞지 않음
- 매핑/API 결과만으로 도달 불가와 계산 실패를 구분할 수 없음

#### 4.3.7 충전 중 재검사

충전 중 매 서버틱 다시 검사한다.

```text
필요 예상 도달 시간 >
남은 방출 시간 + 안전 여유 10틱
```

예:

| 소닉 age | 방출까지 남은 틱 | 요구 도달 시간 |
|---:|---:|---:|
| 0 | 34 | 44 초과 |
| 10 | 24 | 34 초과 |
| 20 | 14 | 24 초과 |
| 33 | 1 | 11 초과 |

한 개체라도 조건을 잃으면 같은 틱에 다음을 수행한다.

- 소닉 충전 취소
- age 34 방출 없음
- 피해·넉백 없음
- 후퇴 navigation 재개

#### 4.3.8 기존 소닉 규칙 유지

다음을 변경하지 않는다.

```text
방출 age 34
전체 행동 60틱
방출 간격 134틱
기존 XZ < 15 / |Y| < 20 사거리
벽 통과
현재 target 방향
반경 1.0 캡슐 판정
다중 대상 각각 1회 피해
공격자 강화 스택 기준 피해
소유자·같은 소유자 워든걸 면역
```

### 4.4 비전투 체력 회복

#### 4.4.1 피해 기록

서버에서 실제 체력이 감소한 틱을 기록한다.

`hurt()`가 호출됐다는 이유만으로 초기화하지 않는다.

다음을 비교한다.

```text
hurt 호출 전 health
hurt 처리 후 health
```

실제 health가 감소했을 때만 마지막 피해 틱을 갱신한다.

따라서 다음은 회복 대기를 초기화하지 않는다.

- 화염 면역으로 피해 0
- 필터로 취소된 피해
- 무적·면역으로 health 감소 없음
- 단순 공격 시도

#### 4.4.2 회복 시작 시점

```text
마지막 실제 피해 후 200틱 무피격
+
추가 80틱 회복 간격 경과
→ 첫 회복
```

즉 마지막 피해 후 첫 회복은 280틱째다.

이후 80틱마다 회복한다.

#### 4.4.3 회복량

```text
회복량 = max(1.0, 최대 체력 × 0.01)
```

예:

| 최대 체력 | 80틱당 회복량 |
|---:|---:|
| 30 | 1 |
| 100 | 1 |
| 500 | 5 |
| 1000 | 10 |

최대 체력을 넘지 않는다.

#### 4.4.4 회복 허용 상태

다음 상태에서도 무피격 조건을 만족하면 회복한다.

- 소유자 추종
- 소유자 주변 배회
- 현지 생활
- 저체력 후퇴
- 후퇴 중 이동
- 파수꾼 대기

공격했다는 이유만으로 회복을 중단하지 않는다.

실제 피해를 받으면 200틱 대기부터 다시 시작한다.

#### 4.4.5 저장·재계산 규칙

- 마지막 피해 틱은 NBT에 저장하지 않는다.
- 로드 직후 즉시 회복하지 않는다.
- 로드 후 새로 280틱을 기다린다.
- 능력치 재계산은 회복으로 취급하지 않는다.
- 강화 스택 증가 시 최대 체력 증가분만큼 회복하는 기존 규칙은 유지한다.

### 4.5 나무문 길찾기·개폐

#### 4.5.1 대상 문

열 수 있음:

- 바닐라 `DoorBlock` 계열 나무문
- 목재 종류가 다른 일반 나무문

열 수 없음:

- 철문
- 다락문
- 울타리 문
- 레드스톤 장치
- 문이 아닌 모드 블록
- 잠긴 문을 가정한 별도 시스템

#### 4.5.2 바닐라 API 우선

Minecraft 1.20.1 공식 매핑에서 다음 계열의 실제 동작을 확인한다.

- `GroundPathNavigation`
- 문 통과 관련 NodeEvaluator 설정
- `DoorInteractGoal`
- `OpenDoorGoal`
- 문 상태 변경 API

바닐라 API가 요구사항을 만족하면 그대로 재사용한다.

문을 직접 파괴하거나 충돌을 무시해 통과하는 코드를 만들지 않는다.

#### 4.5.3 문을 경로로 인식

길들인 워든걸의 육상 navigation은 닫힌 나무문을 다음처럼 취급한다.

```text
파괴 불가능한 벽
→ 아님

열고 통과 가능한 경로 노드
→ 맞음
```

야생 워든걸은 문을 열지 않는다.

#### 4.5.4 문 열기 조건

다음을 모두 만족해야 한다.

```text
길들여진 워든걸
AND
현재 실제 navigation 경로에 포함된 문
AND
워든걸 앞 2블록 이내
AND
닫힌 나무문
AND
문을 통과하는 것이 현재 경로에 필요
```

주변의 관계없는 문을 탐색해 열지 않는다.

문 앞 1.5블록 이내에서 연다.

이중문은 현재 경로가 통과하는 쪽만 열어도 되며, 충돌 폭 때문에 양쪽이 필요하면 두 문을 같은 통과 동작으로 처리한다.

#### 4.5.5 문 닫기

워든걸이 문 반대편으로 완전히 통과한 후 20틱을 기다린다.

다음 조건이면 닫지 않고 10틱 뒤 다시 검사한다.

- 소유자가 문에서 1.5블록 이내
- 같은 소유자의 워든걸이 문에서 1.5블록 이내
- 다른 `LivingEntity`의 bounding box가 문 칸과 겹침
- 현재 워든걸의 경로가 다시 그 문을 향함
- 문이 이미 다른 원인으로 닫힘·제거됨

최대 100틱 동안만 닫기를 재시도한다.

100틱 안에 안전하게 닫지 못하면 열린 상태를 그대로 둔다.

문을 닫기 위해 이동 중인 개체를 밀거나 공격하지 않는다.

#### 4.5.6 전투 중 문

전투 target에게 향하는 유효 경로에 나무문이 있으면 열 수 있다.

단, T14 전투 leash 밖의 target을 따라가기 위해 문을 열지 않는다.

후퇴 경로에 문이 포함되면 생존을 위해 열 수 있다.

### 4.6 문을 통한 소유자 재결합

#### 4.6.1 목적

기존 일반 추종은 소유자와 5블록 이내에 도착하면 멈춘다.

소유자가 문 안쪽에 있고 워든걸이 문 바깥쪽에 있으면 실제로는 분리됐지만 거리만으로는 “도착”으로 판정될 수 있다.

문 재결합은 이 문제를 해결한다.

#### 4.6.2 시작 조건

다음을 모두 만족하면 일반 추종 거리와 무관하게 재결합을 시작한다.

```text
길들여진 워든걸
AND
유효한 소유자가 같은 서버 레벨에 있음
AND
워든걸-소유자 거리 ≤ 48블록
AND
전투 중이 아님
AND
후퇴 중이 아님
AND
파수꾼 착석 상태가 아님
AND
닫힌 문을 통과하지 않는 경로로는 소유자에게 도달 불가
AND
나무문 개방을 허용한 경로로는 소유자에게 도달 가능
```

일반 추종의 12블록 시작·5블록 정지 기준을 적용하지 않는다.

소유자와 1~4블록밖에 떨어지지 않았더라도 문 때문에 공간이 분리돼 있으면 재결합한다.

T14의 48블록 초과 장거리 포기 규칙은 유지한다.

#### 4.6.3 두 경로 비교

10서버틱마다 다음 두 probe를 비교한다.

```text
A. 문 비허용 경로
닫힌 문을 막힌 노드로 취급

B. 문 허용 경로
닫힌 나무문을 열 수 있는 노드로 취급
```

결과:

```text
A 도달 불가
AND
B 도달 가능
→ 문 재결합 시작
```

A 경로로도 도달할 수 있으면 일반 추종을 사용하고, 굳이 문을 열지 않는다.

#### 4.6.4 경로 probe 안전성

경로 비교는 다음을 지킨다.

- 실제 `moveTo()`를 호출하지 않음
- 현재 활성 navigation path를 probe 결과로 덮어쓰지 않음
- door flag를 임시 변경한다면 `try/finally`로 원래 값 복구
- API가 현재 navigation 상태를 변형한다면 독립 probe navigation 또는 evaluator 사용
- 경로 검사 때문에 다른 Goal의 이동이 사라지지 않음

실제 구현 방식은 현재 공식 매핑과 navigation 내부 동작을 확인한 뒤 가장 단순한 안전한 방식을 사용한다.

#### 4.6.5 재결합 동작

문 허용 경로를 실제 navigation 경로로 사용한다.

- 경로상의 나무문을 연다.
- 소유자 쪽 공간으로 이동한다.
- 완전히 통과한 뒤 Part 4.5 규칙에 따라 문을 닫는다.
- 소유자와 정상 정지 거리 안이며 문 비허용 경로로도 도달 가능한 상태가 되면 종료한다.

#### 4.6.6 취소 조건

다음 중 하나면 즉시 재결합을 중단한다.

- 전투 시작
- 후퇴 진입
- 소유자 사망·제거·다른 차원
- 소유자가 문 바깥쪽으로 돌아옴
- 문 허용 경로도 도달 불가
- 철문만 존재
- 소유자 거리 48블록 초과
- T14 현지 생활 상태로 전환

### 4.7 취침 파수꾼 행동

#### 4.7.1 시작 조건

다음을 모두 만족해야 한다.

```text
길들여진 워든걸
AND
유효한 소유자가 같은 서버 레벨에 있음
AND
소유자가 실제 침대에서 수면 중
AND
후퇴 상태가 아님
AND
유효한 전투 target이 없음
```

월드 시간이 밤이라는 사실만으로 시작하지 않는다. 소유자의 실제 수면 상태를 기준으로 한다.

#### 4.7.2 건물 진입

소유자가 집 안 침대에서 자고 워든걸이 문밖에 있으면 Part 4.6 문 재결합이 먼저 실행된다.

워든걸이 소유자와 같은 공간에 들어온 후 파수꾼 위치를 찾는다.

#### 4.7.3 위치 탐색

```text
중심                : 소유자가 사용하는 침대
수평 탐색 반경      : 4블록
허용 거리           : 침대에서 2~4블록
선호 거리           : 3블록
후보 수             : 최대 16개
실패 후 재탐색 대기 : 20틱
```

후보는 다음 조건을 만족해야 한다.

- 고체 바닥
- 워든걸 전체 충돌 공간 확보
- 침대 위가 아님
- 문 칸이 아님
- 소유자의 예상 기상 위치가 아님
- 상자·작업대 등 블록 사용 면을 직접 막지 않음
- 경로로 도달 가능
- 다른 같은 소유자 워든걸의 대기 위치와 충돌하지 않음

별도 전역 자리 배정 시스템은 만들지 않는다. 현재 같은 소유자의 착석 워든걸 AABB와 겹치는 후보만 제외한다.

#### 4.7.4 도착과 착석

```text
도착 판정       : 대기 위치 1블록 이내
도착 후 정지    : 20틱
착석 전환 블렌드: 기존 컨트롤러 전이 6틱 우선 재사용
```

도착 후 20틱 동안 위치를 다시 이동할 필요가 없으면 착석한다.

착석 중:

- navigation 정지
- 몸통 이동 없음
- 일반 추종 중지
- 일반 배회 중지
- 머리 시선 회전 허용
- 기존 상시 호흡·미세 움직임 유지
- headgear 물리 유지

#### 4.7.5 착석 애니메이션

새 애니메이션은 하나만 추가한다.

```text
이름      : guard_sit
종류      : 지속 loop
담당 계층 : 기존 locomotion/pose 계층
```

별도 combat action으로 취급하지 않는다.

기본 방향:

- 다리를 접어 바닥에 안정적으로 앉음
- 상체는 지나치게 숙이지 않음
- 양팔은 몸 옆 또는 무릎 주변에 자연스럽게 위치
- head 본은 고정하지 않아 시선 추적을 허용
- 기존 C1 호흡을 덮어쓰지 않음

구체적인 본 각도는 구현자가 현재 리그와 기존 합성 구조를 확인해 첫 시안을 만들되, 사람 확인 전에는 확정하지 않는다.

기존 1차 애니메이션 값은 변경하지 않는다.

#### 4.7.6 전투 반응

다음 사건이 발생하면 같은 서버틱에 착석 상태를 해제한다.

- 워든걸 피격
- 소유자 피격
- 소유자가 공격한 대상 발생
- 자동 방어 후보 발생
- 유효 target 설정
- 후퇴 상태 진입

일어난 뒤 기존 전투 또는 후퇴 우선순위로 행동한다.

#### 4.7.7 전투 후 복귀

다음을 모두 만족하면 파수꾼 위치로 돌아간다.

```text
유효 target이 60틱 동안 없음
AND
소유자가 계속 같은 침대에서 자고 있음
AND
후퇴 상태가 아님
```

이전 대기 위치가 여전히 유효하면 재사용한다.

유효하지 않으면 새 위치를 찾는다.

#### 4.7.8 종료 조건

다음 중 하나면 파수꾼 상태를 즉시 끝낸다.

- 소유자가 잠에서 깸
- 소유자가 침대에서 이탈
- 침대 제거
- 소유자 사망·제거
- 소유자 다른 차원 이동
- 후퇴 상태 진입
- 소유자와 48블록 초과 분리

종료 후 기존 추종·현지 생활 규칙으로 복귀한다.

### 4.8 최종 행동 우선순위

Goal 등록 숫자는 현재 코드와 vanilla selector 동작을 확인한 뒤 정하되, 의미상 우선순위는 다음과 같다.

```text
1. 후퇴 상태 유지와 안전 지점 이동
2. 후퇴 중 안전 판정을 통과한 소닉붐
3. 자기 피격 반격 대상 선정
4. 소유자 피격 방어 대상 선정
5. 소유자 공격 지원 대상 선정
6. 소유자 접근 적 자동 처리
7. 일반 소닉붐
8. 일반 근접 전투
9. 문을 통한 소유자 재결합
10. 취침 파수꾼 위치 이동·착석
11. 일반 소유자 추종
12. 문 개폐 navigation 보조
13. 소유자 주변 배회
14. 야생·소유자 부재 현지 생활
```

문 개폐 자체는 독립적인 목적 행동이 아니라 현재 navigation을 보조한다.

파수꾼은 전투보다 낮고 일반 추종·배회보다 높다.

## Part 6. 검증 체계

### 6.1 3차 검증의 성격

3차는 서버 AI와 실제 이동이 중심이므로 기본 판정은 **실제 서버 상태와 수치**로 한다.

다만 다음은 수치만으로 최종 판정할 수 없다.

- 후퇴 이동이 자연스러운가
- 문 앞에서 부자연스럽게 흔들리지 않는가
- 문을 적절한 시점에 닫는가
- 파수꾼 위치가 통로를 막지 않는가
- 앉기 애니메이션이 자연스러운가

이 항목의 최종 판정자는 사람이다.

### 6.2 가짜 검증 금지

#### 원칙 1: 실제 상황을 만든다

자동 방어를 검사할 때는 실제 Mob의 target을 소유자로 설정하고 실제 경로를 이동하게 한다.

후퇴를 검사할 때는 실제 체력을 경계값으로 만들고 실제 적을 접근시킨다.

문을 검사할 때는 실제 닫힌 문과 실제 벽 구조를 만든다.

파수꾼을 검사할 때는 실제 플레이어가 침대에서 자야 한다.

로그에 상태 문자열만 넣어 조건을 흉내내지 않는다.

#### 원칙 2: 호출 성공을 성공으로 취급하지 않는다

다음을 실제 결과로 확인한다.

- target이 설정됐는가
- navigation 목적지가 실제로 바뀌었는가
- 경로가 도달 가능한가
- 적과의 거리가 증가했는가
- 문 블록 상태가 실제로 바뀌었는가
- 문 반대편으로 실제 이동했는가
- health가 정확한 틱과 양만큼 바뀌었는가
- 소닉이 age 34에 실제 피해를 냈는가
- 착석 상태가 다른 클라이언트에도 보이는가

### 6.3 측정 유효 조건

모든 계측은 판정 전에 해당 상황이 실제로 만들어졌는지를 출력한다.

| 검증 대상 | 필수 유효 조건 |
|---|---|
| 자동 방어 | 후보의 실제 target UUID, owner UUID, 거리, 경로 도달 여부 |
| 후퇴 | 현재/최대 체력 비율, 활성 위협 수, 선택 목적지 |
| 후퇴 소닉 | 위협별 경로 길이, 예상 속도, 도달 예상 틱, 남은 충전 틱 |
| 회복 | 마지막 실제 피해 틱, 현재 무피격 틱, 회복 예정 틱 |
| 문 통과 | 문 위치·종류·열림 상태, 현재 경로에 포함됐는지 |
| 문 재결합 | 문 비허용 경로 결과, 문 허용 경로 결과 |
| 파수꾼 | owner sleeping, 침대 위치, 후보 위치, 경로 도달 여부 |

유효 조건이 충족되지 않으면 `통과`가 아니라 `측정 불가`로 보고한다.

### 6.4 검증용 코드

필요한 계측과 하네스는 구현 중 임시로 추가할 수 있다.

최종 커밋에는 다음이 남아서는 안 된다.

- T19~T26 전용 상세 로그
- 임시 타겟 강제 Goal
- 검증 전용 AI
- 임시 키 입력 자동화 코드
- 검증 월드용 명령 블록 파일
- 테스트 전용 NBT
- 테스트 전용 패킷
- 임시 LOGGER

기존 `/wardengirl owner`, `/wardengirl power`, `/wardengirl stats` 테스트 API는 유지한다.

### 6.5 두 클라이언트 검증

다음 항목은 실제 두 클라이언트 없이는 완료로 처리하지 않는다.

- 소유자별 자동 방어 독립성
- 다른 소유자의 적 사건 혼입 방지
- 문 상태 동기화
- 착석 상태 동기화
- 한 소유자의 수면이 다른 소유자 워든걸에 영향을 주지 않음
- 같은 소유자의 여러 워든걸 행동
- 다른 소유자 워든걸 소닉 부수 피해
- 서버·두 클라이언트 예외 0

## Part 7. 수치 조정 프로토콜

### 7.1 기본 원칙

Part 4의 값은 3차 구현 시작값이 아니라 **현재 확정값**이다.

구현자가 자연스러움이나 성능을 이유로 임의 조정하지 않는다.

수정은 다음 절차만 허용한다.

1. 현재 값으로 실제 검증
2. 실패 상황과 실제 측정값 보고
3. 변경 후보와 영향 범위 제시
4. 사람 승인
5. 설계서 개정
6. 코드 변경

### 7.2 조정 우선순위

문제가 발생하면 다음 순서로 본다.

| 순위 | 대상 | 확정값 |
|---:|---|---|
| 1 | 후퇴 진입·해제 | 25% / 45% |
| 2 | 후퇴 중심 반경 | 12블록 |
| 3 | 후퇴 이동속도 | 1.6D |
| 4 | 소닉 안전 여유 | 10틱 |
| 5 | 회복 시작·간격 | 200 + 80틱 |
| 6 | 회복량 | 최대 체력 1%, 최소 1 |
| 7 | 자동 방어 반경 | 수평 16 / 수직 8 |
| 8 | 문 닫기 대기 | 20틱 |
| 9 | 파수꾼 위치 | 침대 2~4, 선호 3 |
| 10 | 파수꾼 복귀 | 전투 종료 후 60틱 |

### 7.3 구조 문제와 수치 문제를 구분한다

다음은 수치를 바꿔 해결하지 않는다.

- 경로가 문을 인식하지 못함
- navigation이 서로 덮어씀
- 자동 방어가 다른 소유자 사건을 읽음
- 후퇴 중 근접 Goal이 실행됨
- 소닉 취소 후 피해가 발생함
- 문 비허용·허용 경로가 동일하게 나옴
- 착석 상태가 다른 클라이언트에 보이지 않음

이 경우 구조를 수정하고 동일한 수치로 다시 검증한다.

## Part 9. 알려진 제약

| 제약 | 영향 | 대응 |
|---|---|---|
| `Mob.getTarget() == owner` 기반 | target을 쓰지 않는 특수 공격은 자동 방어 전 탐지 못함 | 실제 피격 후 T15 소유자 피격 사건으로 반격 |
| 적 navigation 경로 probe | 복잡한 지형에서 비용·오판 가능 | 반경·검사 주기 제한, 실제 `canReach` 확인 |
| 도달 시간은 근사치 | 실제 MoveControl, 점프, 효과에 따라 차이 | 이동속도 1.5배와 10틱 안전 여유로 보수 판정 |
| 문 경로 비교 | 매핑 내부에서 flag 변경이 navigation 상태에 영향을 줄 수 있음 | probe 후 상태 복원 또는 독립 evaluator |
| 문은 집을 의미하지 않음 | 문이 있는 야외 구조도 통과 가능 | 현재 소유자 경로에 필요한 문만 처리 |
| 철문 미지원 | 소유자가 철문 안에 있으면 따라 들어가지 못함 | 강제 개방·순간이동하지 않음 |
| 장거리 순간이동 없음 | 48블록 초과 분리 시 집으로 따라오지 않음 | 기존 T14 현지 생활 유지 |
| 파수꾼 위치는 의미적 가구 인식이 아님 | 일부 협소한 집에서 좋은 자리를 못 찾을 수 있음 | 유효 위치가 없으면 서서 침대 주변 대기 |
| 다수 워든걸 | 협소한 공간에서 모두 앉을 자리가 없을 수 있음 | 겹치지 않는 후보만 사용, 없으면 서서 대기 |
| 회복은 허기와 무관 | 플레이어와 완전히 동일한 생존 규칙은 아님 | “서서히 회복”만 재현 |
| `guard_sit` 신규 동작 | 첫 시안이 시각적으로 부자연스러울 수 있음 | 사람 확인 후 별도 개정 |

## Part 10. 금지 사항

1. 주변 몬스터를 종류만 보고 자동 공격하지 않는다.
2. `Zombie.class` 등 특정 적대 몹 목록을 만들지 않는다.
3. 소유자 주변에 있다는 이유만으로 공격하지 않는다.
4. `Mob.getTarget() == owner`와 경로·반경 조건을 생략하지 않는다.
5. 자동 방어 검사마다 현재 유효 target을 교체하지 않는다.
6. `alertOthers()` 또는 집단 어그로 전파를 사용하지 않는다.
7. 전역 위협·소유자·문 관리자를 만들지 않는다.
8. 후퇴 중 근접 공격을 허용하지 않는다.
9. 적 하나라도 방출 전에 도달 가능하면 후퇴 소닉을 시작·유지하지 않는다.
10. 후퇴를 위해 순간이동하지 않는다.
11. 소유자 중심 12블록을 벗어나 무한 도주하지 않는다.
12. 피해를 받는 중 지속 회복하지 않는다.
13. 로드·능력치 재계산으로 체력을 회복하지 않는다.
14. 철문을 손으로 열지 않는다.
15. 문을 파괴하지 않는다.
16. 경로에 필요하지 않은 주변 문을 열지 않는다.
17. LivingEntity가 통과 중인 문을 닫지 않는다.
18. 문 재결합으로 T14의 48블록 포기 규칙을 우회하지 않는다.
19. 문 재결합 경로 probe로 현재 navigation을 덮어쓰지 않는다.
20. 집·방·소유자 문 사용 기록을 전역 시스템으로 만들지 않는다.
21. 파수꾼이 전투나 후퇴를 막지 않게 한다.
22. 파수꾼을 야생 워든걸에 적용하지 않는다.
23. 기존 1차 애니메이션 값을 수정하지 않는다.
24. 새 착석 동작 외의 애니메이션을 추가하지 않는다.
25. 업고 도망가기·머리 탑승을 이번 단계에 포함하지 않는다.
26. 새 범용 패킷·NBT·SynchedEntityData를 불필요하게 추가하지 않는다.
27. 멀티플레이 전용 로직을 만들지 않는다.
28. 태스크를 건너뛰거나 자동 진행하지 않는다.
29. **[사람 확인]** 항목을 구현자가 스스로 판정하지 않는다.
30. 설계서에 없는 편의 기능을 임의 추가하지 않는다.

## Part 11. 개정 이력

이 문서는 구현 중 발견된 사양 오류를 반영해 개정된다.

**개정 권한은 사람에게만 있다.** 구현자는 사양 충돌이나 바닐라 API 제약을 발견하면 코드를 임의 변경하지 않고 보고한다.

각 항목은 날짜 / 변경 내용 / 근거 순서로 기록한다.

---

### 2026-07-31 — 3차 설계서 초안 작성

**변경.** 기존에 논의했던 업고 도망가기·머리 탑승 기능을 3차 범위에서 제외하고 다음 기능으로 3차 범위를 재정의했다.

- 소유자를 노리고 접근 가능한 적 자동 처리
- 저체력 후퇴
- 후퇴 중 안전 소닉붐

- 취침 파수꾼

**근거.** 차수마다 같은 태스크 번호를 재사용하면 완료 보고, 커밋, 검증 로그, 설계서 개정 이력에서 어느 단계의 태스크인지 혼동될 수 있다. 프로젝트 전체에서 태스크 번호를 연속해서 사용한다.
